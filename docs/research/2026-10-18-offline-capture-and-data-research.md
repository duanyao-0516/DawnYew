# DawnYew 离线快速记账与数据能力调研

日期：2026 年 10 月 18 日。对应用户新增重点：图表、JSON 或 Excel 导入导出、生物识别，以及稳定的快速记账方式。沿用完全离线、免费、Android 优先、保留跨平台能力的约束。

建议首版采用**快速手动录入加主动分享截图的本地 OCR**。JSON 与 Excel 分别承担完整恢复和账单交换，本地应用锁覆盖所有数据入口。语音作为第二候选；无障碍支付页识别不作为首版依赖。

这个选择是基于机制、依赖和故障范围的工程判断，不是已经完成的准确率排名。竞品资料没有提供可直接比较的统一测试数据；OCR 引擎仍须通过下述离线样本验证才能定型。

## 市面上的快速记账怎么做

| 产品 | 官方确认的入口和处理 | 对离线要求的影响 |
| --- | --- | --- |
| iCost Android | 在支付成功或账单详情页截图，通过系统分享给应用，确认账单；另有需要无障碍及悬浮窗授权的入口 | 其第三方服务清单包含 DeepSeek 辅助解析，不能直接照搬为纯离线方案 |
| 钱迹 Android | 无障碍提取支付页；截图可分享给 AI 记账，更新记录加入重复检测 | 官方称传统页面识别在本地进行，但账单同步及可选图片上传是另一条数据链路；截图 AI 不能据此认定为端侧 |
| 薄荷记账 | 截图识别，Android 主动 AI 和语音入口，以及通知栏或图标快捷入口 | 官方资料不足以确认 Android 图像和语音全程端侧，不能据此选定离线引擎 |

依据：[iCost Android 快速记账](https://help.icostapp.com/guide/ai/ai_android.html)、[iCost 第三方服务清单](https://help.icostapp.com/guide/law/sdk.html)、[钱迹 Android 自动记账](https://docs.qianjiapp.com/auto/qianji_auto_android.html)、[钱迹 Android 更新记录](https://docs.qianjiapp.com/change-log/change_log_android.html)、[薄荷 Google Play](https://play.google.com/store/apps/details?id=melandru.lonicera&hl=zh&gl=cn)。这些是厂商说明，不是本项目实测。

值得借鉴的是“生成草稿、检查、确认、纠错”这一流程。识别算法的输出与最终账单之间应有明确边界，图片能转成文字并不意味着金额、退款、优惠和支付状态已经解析正确。

## 方式比较与建议

| 方式 | 操作路径 | 稳定性所依赖的条件 | 本项目建议 |
| --- | --- | --- | --- |
| 金额键盘与常用分类 | 打开记账、填金额、选分类、保存 | 应用自己的界面与规则 | 保留为所有设备都可用的核心入口 |
| 无障碍页面识别 | 支付页面出现后自动识别或弹出 | 第三方控件树、页面版本、后台保活、授权和渠道规则 | 首版不依赖；用户已有体验不佳的反馈 |
| 主动分享截图加本地 OCR | 截图、分享或选图、确认草稿 | 图片清晰度、离线模型、字段解析和确认界面 | 首版优先验证的增强入口 |
| 系统端侧语音 | 录音、端侧转写、确认草稿 | 系统端侧服务和已安装中文语言资源 | 仅作有条件设备增强候选 |
| 随包离线语音模型 | 录音、应用内转写、确认草稿 | 模型许可、包体、内存、噪声和数字转写表现 | 第二候选；需独立测量后决定 |

截图方案仍需适配支付页面的文字和金额语义，但不需要常驻监听第三方控件树，也不依赖后台捕获时机。这是推荐它优先验证的原因，不代表它能够覆盖所有截图或自动记账永不出错。

Android 官方支持应用接收系统分享的图片，也建议用户有机会确认和编辑接收内容。应用可把这个入口和系统选图入口合并到同一套草稿处理流程。[Android 分享接收指南](https://developer.android.com/develop/ui/compose/sharing/receive?hl=en)

## OCR 引擎候选

Google ML Kit 提供随包模型和经 Google Play 服务下载模型两种文字识别方式，中文模型可随包；后者不符合首次安装后就完全离线的要求。但即使随包，官方隐私说明仍提到性能与使用指标发送及可能的服务器联系，因此不能仅凭“端侧识别”认定满足本项目“无联网、无遥测”的边界。[安装方式](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)、[隐私说明](https://developers.google.com/ml-kit/terms)、[数据收集说明](https://developers.google.com/ml-kit/android-data-disclosure)

优先验证可随包部署、可审查依赖的本地 OCR 路线，例如 PaddleOCR 移动模型与 ONNX Runtime。PaddleOCR 官方 Android 示例把检测、识别模型放入应用 assets，在设备上推理。这证明存在移动部署路径，并不能直接证明本项目包体、准确率、运行时无请求或所有机型性能合格。[官方 Android 部署示例](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/inference_deployment/cross_platform/android_deployment.en.md)

定型前检查具体引擎及模型许可证、原生 ABI、内存、包体、冷启动、首次断网可用性及依赖遥测。生产包不包含模型下载器或自动远程资源更新。开发阶段获取依赖与模型不等于产品运行时联网。

## 首版截图范围

输入为用户主动分享或选择的一张 PNG/JPEG 图片，优先覆盖微信和支付宝的**单笔消费支付成功页与单笔消费详情页**。不申请持续读屏、全相册监听或后台截图采集。

一张图生成至多一笔待确认草稿，展示图片预览、金额、类型、日期、分类、账本及识别提示。原始图片默认只作为处理过程中的临时内容，取消或保存后清理应用临时副本，不删除用户相册原图。

多笔账单列表、长截图、模糊图片、转账、退款、优惠抵扣复杂组合和非成功支付页，首版不自动构造正式流水。金额不唯一时列出候选，无法确认时保留手动补全。退款仍由原支出发起，避免脱离原消费关联。

日期识别不到时可以提出“今天”的建议，但必须标记为待确认；分类和账本同样是建议，不能仅凭付款渠道自动选择用途账本。即使全部字段都有结果，也需用户确认才入账。

同一提交动作保证幂等；相同来源图片、相同金额日期等只形成重复提示，不能据此直接删除真实记录。无论何种入口，均经过应用锁、草稿确认和正式账务校验。

## 离线语音的可行性

普通 Android `SpeechRecognizer` 可能把音频交给远程服务；`EXTRA_PREFER_OFFLINE` 是偏好，识别器实现可以忽略。它不足以支撑本项目的离线承诺。[SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer)、[离线偏好参数](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_PREFER_OFFLINE)

Android API 31 起有明确的端侧识别器接口；API 33 起可以进一步查询已经安装的语言和仍需下载的语言。系统有端侧服务不等于已经具备中文。未能确认中文离线能力时，入口应不可用，不下载模型、不转向云服务。[语言能力说明](https://developer.android.com/reference/android/speech/RecognitionSupport)

如果要覆盖没有预装服务的设备，可评估随包引擎及中文模型。sherpa-onnx、Vosk 和 whisper.cpp 均有官方离线或移动端路径；每个模型的许可和移动性能仍需独立验证，不能用服务器测评替代手机数据。[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)、[Vosk](https://alphacephei.com/vosk/)、[whisper.cpp](https://github.com/ggml-org/whisper.cpp)

语音若进入后续版本，第一阶段限制为“一次一笔”，先转写“午饭三十二元五角”这类句子，再由本地规则提取金额和分类，展示草稿。音频默认不保留。系统输入法的语音按钮由输入法实现，不能作为 DawnYew 已提供离线语音的证据。

## 生物识别是本地应用锁

AndroidX BiometricPrompt 可调用设备的系统生物识别界面，系统凭据可作为后备；硬件不存在、未录入、暂时不可用和认证失败要分别处理。用户启用应用锁前先验证可用认证方式；失败或取消保持锁定，不能自动放行。[Android 官方指南](https://developer.android.com/identity/sign-in/biometric-auth)、[BiometricManager](https://developer.android.com/reference/androidx/biometric/BiometricManager)

应用不获取或保存指纹、面部模板。这里保护的是进入应用和操作数据的入口，不自动等于数据库加密。导出文件也不继承应用锁；完整备份的口令加密另行设计。没有生物硬件但有系统 PIN 的设备，可使用系统凭据；两者都没有则先引导设置设备锁屏，不展示虚假的“已保护”状态。

## JSON 与 Excel 的分工

建议两种格式均支持：

- **JSON**：公开、带版本的完整数据协议；保留账本、分类、稳定 ID、退款关联、预算和回收站。支持明文 `.json` 导入导出，完整恢复采用整体替换。另提供使用同一协议的口令加密备份容器，明确区分扩展名与用途。
- **Excel**：DawnYew 自身模板与导出使用真实 `.xlsx`，用于流水阅读、编辑和批量导入。用户已确认首版同时直接导入微信、支付宝历史账单，具体模板细节之后提供；平台文件类型和字段不能预先假定与自身 XLSX 一致。导入前统一预览账本分类映射、错误、重复、排除项及影响总额。

稳定 ID 与内容都相同的流水可确定为重复；同 ID 内容变化属于冲突，不静默覆盖。没有 ID 的外部记录即使金额和日期一样也只能提示疑似重复。正式导入前必须明确新增、跳过和待解决项，失败不部分污染数据。

平台原始流水标识按已验证的来源范围判断唯一性，不把不同平台的同值编号混为一条；跨手动、截图和文件来源的模糊重复需用户核对。失败、关闭、资金划转、退款及汇总行按确认的模板语义区分，不能全部转换为普通收入或支出。支持版本、状态映射及样本预期值待模板补充，不据此声称现已具备导入能力。

Excel 不是完整备份，宏、公式、外部链接不执行；不把 CSV 改扩展名当作 Excel。自身模板采用 `.xlsx`；微信、支付宝实际文件格式及可能的解包需求待样本确认，不要求用户先人工改为 DawnYew 模板。用户自行取得平台账单后，应用在本机解析，不接在线表格、支付平台登录或在线抓取。

## 图表设计原则

首版包含收入与净支出趋势、原始支出分类占比、按账本的支出对比及预算进度。点击图表项目可下钻到相同期间和归属的流水，并提供等价数据表。

退款口径与明细一致。分类占比用非负的原始支出，净支出和退款另列；趋势和对比若含负净支出，则明确显示零轴和正负方向。无数据、全额退款、只有收入和历史归档账本均要有明确展示。

## 定型验证计划

下一阶段使用经授权的脱敏图片或合成样例做本地验证，不读取用户相册或真实账单作为默认测试数据。所有数字均为建议门槛，不是当前实测成绩。

| 验证项 | 建议样本与门槛 |
| --- | --- |
| 支持范围内识别 | 160 张单笔成功消费截图，微信和支付宝各 80 张，包含深浅色和不同字号；金额完全匹配率至少 98%，类型正确率至少 99% |
| 异常样本 | 80 张多金额、模糊、退款、转账、支付失败和多笔列表；所有样本均不得未经确认写入账本；歧义必须进入待核对或手动状态 |
| 设备差异 | 至少三台不同厂商 Android 真机，含一台未装 Google Play 服务的设备；每台全新安装后首次断网识别 |
| 速度与资源 | 统一 1080p 截图，解锁后开始识别至草稿可编辑 P95 ≤3 秒；记录冷启动、包体增量、峰值内存和发热，不预填结果 |
| 网络与权限 | 联网状态观测应用及所用组件，无模型下载、账单上传和遥测；拒绝可选权限仍能手动使用 |
| 录入价值 | 5 人同一组 20 笔任务，对比手动与截图完整耗时，包含截图、分享、解锁、纠错；截图中位耗时至少下降 20%，且最终账单无错 |
| 数据和锁 | JSON 完整往返、微信/支付宝历史账单及自身模板导入、重复及冲突处理、认证失败、外部分享绕过、取消和中断，全部有用例；模板样本待用户补充 |

如果截图路径无法达到业务正确性、无联网或操作效率门槛，应回到需求评审调整范围或引擎，不能仅用手动兜底宣称截图功能已经验收。语音是否进入首版则根据同一口径的准确性、耗时、覆盖面和资源证据再决定。
