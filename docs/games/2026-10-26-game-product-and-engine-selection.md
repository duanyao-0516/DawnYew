# 小游戏产品形态与技术选型

日期：2026-10-26。用户已确定 Unity + C#，最新范围为先做好独立 Android APP，暂不接入微信、抖音等小游戏渠道。本文保留横向调研，当前决定与早期 Godot 推荐有明确区分。

## 1. 已确定的技术方向

**一个独立、完全离线的小游戏合集 APP；采用 Unity + C#；在 [XanaduYonder](https://github.com/duanyao-0516/XanaduYonder) 中按游戏方式重做 2048。本阶段只实现 Android APP，不引入小游戏渠道 SDK 或构建目标。**

用户明确不需要维护引擎，并优先考虑广泛生态、后续学习和扩展。此前偏重引擎开源可控的 Godot 推荐已被本决定取代。Unity 支持原创游戏代码开源；引擎本身是否开源不再作为首要选型条件。编辑器发行版、具体补丁版本和 Android 构建模块在最小 APP 工程验证后固定；渠道 SDK 兼容性留待渠道需求启动后验证。

用户已明确的边界：

- DawnYew 负责记账和聚会小工具，猜拳保留原入口和功能。
- 2048、跳跃、堆叠拾取等个人小游戏进入独立产品。
- 独立 APP 安装后离线运行，不依赖账本、OCR、无障碍、登录、会员或云存档。本阶段不接入微信、抖音等渠道。
- 不做旧 2048 存档迁移；新产品从新存档开始。本轮没有删除设备中的旧数据。
- “跳一跳”“抓大鹅”在本文指蓄力跳跃、堆叠拾取消除的玩法方向，采用自研代码和素材。

## 2. 一个合集，还是多个 APP？

| 形态 | 优点 | 代价 | 当前判断 |
| --- | --- | --- | --- |
| 独立合集 APP | 安装一次；统一大厅、设置、音效、触感、存档；同一引擎无需分散在多个安装包中 | 更新一起发布；资源总量增加；必须按需加载和退出释放 | **推荐**，符合短局休闲、持续添加玩法的目标 |
| 每个游戏一个 APP | 品牌、发布节奏、体积和故障范围分开；可分别选择技术栈 | 多次安装；重复维护签名、版本、分发资料和基础功能 | 当前收益不足 |
| 先合集，成熟游戏另发独立 APP | 先统一开发，再按实际需求独立运营 | 需要保持模块边界；独立导出仍要配置和验收 | **演进路径**，现在不同时维护多个产品 |

拆分应由真实产品差异驱动：独立用户群或品牌、资源规模显著增长、不同联网/权限需求，或发布节奏长期相互拖累。游戏数量从 3 个增加到 6 个，本身不足以构成拆分理由。

建议新产品使用独立仓库、应用 ID 和构建链。DawnYew 不导入其模块或引擎。小游戏内部模块化，以后可以通过导出配置组合成独立产品。

## 3. 评估依据

| 玩法 | 主要需求 | 容易遗漏的问题 |
| --- | --- | --- |
| 2048 | 稳定方块身份、移动/合并/生成动画、连续输入、规则与表现分离 | 直接替换数字不能构成完整动效；动画不能影响合并规则 |
| 蓄力跳跃 | 按压反馈、可控轨迹、落地判断、镜头跟随、快速重开 | 输入延迟、不同帧率、暂停后残留蓄力状态 |
| 堆叠拾取消除 | 多物体碰撞、休眠/唤醒、遮挡拾取、取走重排、槽位和消除规则 | 物理峰值负载、拾取被遮挡对象、重复拾取、持续发热 |

按小团队自研、Android 优先、离线运行、2D 与轻量 3D 共存评估。当前没有同素材包体/FPS实测，不以任意分数制造性能排名。

## 4. 引擎横向对比

| 方案 | 匹配能力 | 主要代价或风险 | 适用结论 |
| --- | --- | --- | --- |
| **Godot + GDScript** | 同一套场景、动画、2D/3D、资源工具；MIT；独立 Android 导出 | shader/pipeline 首次使用可能卡顿；渲染器与硬件兼容性要验证；需要实际物理和资源优化 | 保留调研对照；用户已选择 Unity |
| **Unity + C#** | 2D/3D、PhysX、场景制作和性能分析，适合较重 3D 内容 | 管理编辑器授权和工具版本；体积、启动和内存仍需实测 | **已选定**，优先满足生态学习与后续 2D/3D 扩展 |
| **Cocos Creator + TypeScript** | 2D/3D、原生 Android、本地 Asset Bundle、多个小游戏渠道 | Creator 3.8 与 COCOS 4 属不同代际，须锁定版本；小游戏渠道适配有价值，但不是实现渠道分发的唯一方案 | 渠道方案对照；不因新增微信目标自动更换已定技术栈 |
| **Defold + Lua** | 2D/3D、Bullet、glTF；Collection proxy 支持按游戏装卸；组件裁剪 | 原生扩展及部分构建路径默认使用构建服务；3D 制作流程适配团队程度需试做 | **轻量备选**，不能以“只有 2D”排除 |
| **libGDX + Kotlin/Java** | Kotlin 经验可用；渲染、资源、Box2D/Bullet；Apache 2.0 | 更偏代码框架，编辑、预览、关卡制作工具需要另外组织 | 偏代码开发的备选，本次不优先 |
| **Phaser + WebView** | JS/TS、2D 工作流，本地资源可离线打包 | Phaser 本身是 2D；真实 3D 堆叠需额外库；WebView 输入/音频/生命周期也要验证 | 全部玩法为 2D 且 Web 优先时考虑 |
| **Unreal** | 完整 3D、物理、Blueprint、移动端工具 | 当前短局休闲收益不足以支撑其制作与渲染配置复杂度 | 当前不选，高规格 3D 产品重评 |
| **Compose / 自写 Android 渲染循环** | 熟悉现有技术，2048 可以做好动画 | 后续 3D、碰撞、资产制作需增加大量能力；两套呈现体系不利于统一制作 | 猜拳沿用，个人小游戏转入引擎 |

表中的适用结论是工程判断，不是官方性能结论。详细能力、许可和来源见两份专项调研。

### 当前授权与版本事实

- Godot 官方发布记录当前列出 4.7.2 stable。正式工程应固定编辑器与匹配导出模板，不追随滚动 latest。[发布记录](https://godotengine.org/download/archive/)
- Unity Runtime Fee 已取消；Personal 当前门槛为最近十二个月 20 万美元，需按实际主体资格核对，不能沿用已取消的收费政策淘汰 Unity。[政策](https://activation.unity3d.com/products/pricing-updates)、[资格](https://unity.com/pages/license-compliance)
- Creator 3.8 的引擎运行时和编辑器协议应分别看；新 COCOS 4 已有 MIT 源码，但本次发布列表仍为 alpha，不直接选作生产基线。[Creator 许可](https://github.com/cocos/cocos-engine/blob/v3.8.9/LICENSE.md)、[COCOS 4 发布](https://github.com/cocos/cocos4/releases)
- Defold 支持 3D，许可允许商业发布游戏，但不能商业出售引擎/编辑器本身。[许可](https://defold.com/license/)

玩家离线运行与开发时下载工具、依赖、模板或完成授权是两个问题。最终发布仍需核查 Manifest 和依赖，不能仅凭引擎名称断言没有网络能力。

## 5. Unity 决策与后续渠道研究

当前选择依据是学习生态、现成工具和长期增加玩法的便利性，不需要自行维护引擎。原创 C# 代码可以单独选择开源许可，Unity 和第三方内容继续遵循自己的许可；项目开源与引擎开源分别处理。[Unity 内容权属条款](https://unity.com/legal/terms-of-service)

微信有官方 Unity/团结引擎 SDK，抖音有官方 Unity WebGL 与 C# SDK 路线。平台转换主要复用 C# 玩法与资源，不承诺把现成 APK 直接转换为所有渠道，也不承诺不做任何适配即可上线。[微信 SDK](https://github.com/wechat-miniprogram/minigame-tuanjie-transform-sdk/blob/main/README.md)、[抖音接入指南](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/game-engine/rd-to-SCgame/unity-game-access/install-connect/sc_access_guide)

计划中的 Android 构建包含全部游戏与大厅。早期渠道建议为微信/抖音初期各按一个游戏出包，复用核心规则、场景和美术，注入对应平台适配层；该建议保留为后续研究，不属于本阶段实施范围。

Unity 全球版与团结引擎是不同发行/版本线。团结是 Unity 中国基于 Unity 2022 LTS 定制的引擎，提供国内渠道集成；不能把它视为 Unity 6 的同义词，也不能假定工程可无损双向转换。[团结官方说明](https://unity.cn/tuanjie/help-center)

第一步在 XanaduYonder 中采用最小 2048 场景，验证 Android 输入、资源、存档及恢复，再固定编辑器和 Android 构建模块的确切组合。微信、抖音的转换 SDK、开发者工具与宿主验证均暂缓，不作为 APP 开发与发布的前置条件。

后续渠道的调研路径、限制和来源见 [Unity 多平台发布调研（渠道接入暂缓）](2026-10-26-unity-minigame-publishing.md)。

## 6. 独立合集的模块设计

```text
小游戏 APP
├── 大厅与设置：目录、返回、声音、触感、主题
├── 运行协调：加载、暂停、恢复、退出、释放
├── 公共服务：按 gameId 隔离的存档、音频、随机源
├── 平台适配：Android；其他渠道待实际需求启动后增加
└── 游戏模块
    ├── 2048：规则、状态、场景、动效、测试
    ├── 蓄力跳跃：规则、场景、镜头、素材、测试
    └── 堆叠拾取：物理、拾取与消除、素材、测试

DawnYew：账务、截图记账、工具箱、猜拳
         与小游戏 APP 无运行时依赖
```

每款游戏具有稳定 `gameId`、标题、入口场景、存档版本和独立资源目录。宿主只提供本游戏的存档句柄、音频/触感设置及退出能力；游戏不直接操作其他存档或 DawnYew 数据。

“插件”首先是随安装包发布的场景模块和注册表，不是动态下载脚本、APK 插件或安全沙箱。不预装 Python，不为了尚不存在的游戏引入多语言运行时。Unity 中以 asmdef 程序集定义隔离规则、游戏和平台代码，以 Scene、Prefab、ScriptableObject 组织入口及资源。编译依赖边界不等于运行时安全沙箱。

大厅按需加载当前游戏。退出时按资源所有权停止协程、音频、动画和计时器，解绑事件，卸载场景并释放资源句柄；检查静态引用和资源缓存，不将场景退出视为资源已全部回收。规则层使用独立 C#，平台存档和宿主生命周期通过接口注入。

存档独立版本化，校验大小与类型，失败可见，提交可恢复。不把简易 JSON 教程等同于完整持久化实现。新产品不读取或迁移旧 DawnYew 游戏存档。

## 7. 2048 重做范围

**重做表现与交互，不继续搬运 Compose 页面。** 旧规则测试样例可以作为验收参照，新实现重新验证规则；不为复用少量 Kotlin 代码引入桥接运行时。

已拆除的 Compose 实现直接按盘面数字绘制格子，没有完整表达方块从哪里移动、哪些方块合并。Compose 本身支持位置、缩放等动画，不能由旧实现推导出它天生不流畅；改用引擎的理由是统一后续游戏制作能力。[Compose 动画](https://developer.android.com/develop/ui/compose/animation/quick-guide)

| 层次 | 责任 |
| --- | --- |
| 规则层 | 输入方向和随机源，输出新棋盘以及移动/合并/生成事件；每格每步至多合并一次，无效移动不生成；分数、撤销、继续游戏独立可测 |
| 表现层 | 保留方块身份；位移后播放合并反馈和新方块出现；统一时序、缓动、音效与可关闭触感；不突然替换整盘数字 |

快速连划使用有上限的输入缓冲，每步提交后依次消费，避免吞输入、重复合并或长期积压。后台、撤销、重开时取消未消费输入，使画面与逻辑收敛；存档记录逻辑结果，不记录半程 Tween。2048 不需要刚体模拟，引擎负责表现和输入即可。

## 8. Unity Android APP 运行验证

先完成 Android APP 的 2048 最小切片，之后增加跳跃和堆叠场景。以下是**建议目标，不是已有测试结果**。原型阶段第一步应固定设备型号、系统、刷新率、画质、分辨率及温控条件，并在测量前约定帧时间、冷启动、内存和体积的通过上限；当前文档是选型评审，不是完整的性能验收协议。

| 检查项 | 方法 |
| --- | --- |
| 2048 手感 | 连划、连续合并、撤销/重开，验证动画、输入队列、棋盘一致 |
| 跳跃反馈 | 蓄力到起跳响应、落地、镜头移动；暂停恢复不意外起跳 |
| 3D 压力 | 同素材 50/100/200 个简单刚体作为测试梯度，检查休眠、唤醒、遮挡拾取、取走重排；数量不是已定产品规格 |
| 帧节奏 | 同一中低档真机、同画质/分辨率；记录 CPU/GPU 时间、P50/P95/P99 帧时间与漏帧；以 60 Hz、16.67 ms 帧预算为初始目标，120 Hz 后续评估 |
| 首次卡顿 | 冷启动、首次进场、首次材质/粒子/音效，分别记录预热前后 |
| 体积与内存 | 实测 APK/AAB、安装体积、冷启动、峰值内存；反复进出检查持续增长 |
| 热运行 | 至少连续运行 15 分钟，观察降频后的帧时间、发热及功耗趋势 |
| 离线/生命周期 | APP 安装后断网完成玩法，验证前后台、杀进程恢复与资源释放 |

平均 FPS 不能替代帧节奏，显示刷新同步及迟到帧也影响流畅度。[Android Frame Pacing](https://developer.android.com/games/sdk/frame-pacing)
