## 3. 推荐页面树与交互路径

一级顺序固定为 **主页（沿用内部“首页”路由可减少迁移）、账户、统计、更多、我的**。视觉使用五个等宽线性图标，正常态不显示冗长标签；语义始终提供页名与 selected 状态，点击范围至少 48dp。保留“我的”长按进入 Debug 的手势与无障碍长按动作。

- 主页：账本下拉 / 搜索 / AI 空占位 → 本月支出 → 未入账条件面板 → 最近交易 → 预算概览 → 日历 → 进行中存钱计划 → 面板配置；右下 FAB → 金额底部面板 → 完整记账页。
- 账户：净资产头图卡 / 隐藏金额 / 添加 → 账户类型分组 → 账户详情 → 关联流水；底部隐藏账户。添加类型 → 本地账户表单 → 保存后原组出现；网络/行情字段只留空占位。
- 统计：默认分类环图、日趋势、月度收支三卡 → 每卡详情 → 同范围流水；底部面板目录 → 非受限本地统计配置。17 项目录可以保留，但受限项没有伪造图表。
- 更多：往来管理 2×2（借入、借出、报销、往来）；计划管理 2×2（周期、分期空占位、预算、存钱）；下方“实用工具”保留原有五项，不改变原工具的生命周期和状态恢复。
- 我的：本地身份头部 / 消息占位 / 设置 → 记账天数、交易数、净资产摘要 → 会员空占位 → 分类/项目/商家/标签、导入/导出/共享占位/账本两行四列 → 自动/OCR、组件、日志空占位、备份分组 → 货币/安全/活动占位/提醒、客服占位/本地手册/评分占位/分享占位。回收站与保护副本等 DawnYew 已有能力放入本地数据/备份/安全子页，保持可达。

跨页返回规则：从任何对象进入流水，记录来源页和原 scope；详情返回对象流水，流水返回来源页；从流水编辑保存返回原详情/流水上下文；不能沿用当前 `finishBack()` 中“账单详情总回明细、drill 总回统计”的硬编码覆盖新增来源。

## 6. 占位清单与例外

**已经有证据的占位**：登录/账号、同步、共享邀请、云日志/撤销；会员页面；主页账户追踪；交易拆分/手续费；季度统计；分期；历史余额/账户占比受限区域；导出交易图片；非默认主题权益；受限 Widget；WebDAV/远程备份；行情搜索/同步；外部客服、评分、活动、在线分享目的地、AI 会话。其它仅静态疑似受限项，先查对应代码/报告再归类，不能把整个模块一概当作 VIP。

两个明确例外来自本次用户约束：**已有离线 OCR、应用锁、本地备份不能因参考产品某相似功能收费而移除或占位**。它们是 DawnYew 已实现且要求保留的能力。薄荷新增的专属受限分支可空占位。消息/作者/多人统计无本地多人来源时也不伪造用户和数据。

对“占位”的具体决议：保留原入口位置、名称及可返回的空内容页；不制作付费介绍、权益枚举、手机号表单、购买或跳转动作。一级我的身份头部直接是本机用户，不把登录作为应用门槛。空占位内容不纳入“离线功能已完成”的声明。

## 7. 可分工边界与接入顺序

1. **总集成所有者**：`DawnYewApp.kt`、`Theme.kt`、`AppGlyph.kt`、`StatisticsNavigation.kt`、`AppController.kt` 的共同入口，以及新增共享组件。先明确页面 props/route/event 类型，之后由集成者统一接线；不要让多个 agent 同时改这些文件。
2. **交易 UI 所有者**：`EntryScreens.kt`、新增 `TransactionsScreen.kt`、`AmountEntrySheet.kt`、本地选择器；可独立写纯布局和 presentation 计算器，但 `EditorDraft`、`EditorChange` 及命令字段须和领域所有者对齐后单人编辑。
3. **账户/更多 UI 所有者**：新增 `AccountsScreen.kt`、`PlanScreens.kt`、`ObligationScreens.kt`，改 `MoreScreen.kt`；依赖 core 的账户/计划/往来契约；不碰 OCR/锁/备份。
4. **首页/统计/我的 UI 所有者**：`HomeScreen.kt`、`StatisticsScreen.kt`、新增 `ProfileScreen.kt` 与管理页面；账户汇总/对象管理由对应接口提供，不能自行推导另一套净资产。
5. **领域/存储/协议所有者**：账户/交易元信息/计划/对象模型、命令、验证、SQL/数据代际、旧备份兼容、统计/查询。优先产出可引用的数据结构和行为测试，再释放 2–4 的接线。
6. **Android 平台所有者（如实现组件/提醒）**：仅 Widget/通知权限/本地调度接口，及必须的 manifest/resources；不重写 `MainActivity` 的授权会话、文件回调和恢复过程。

实际并行时 UI 三组可分开新增文件，`DawnYewApp.kt` 由总集成者序列化接入。若并发槽不够，先做领域契约与交易 UI，再做账户/计划 UI 与首页/统计 UI。工作区共享，不通过换分支/重置工作树隔离。

开发次序：先方案交叉 review 并记录决议 → 领域/存储/备份契约 → 五 Tab/主题/共用组件 → 交易与账户真实闭环 → 往来/预算/周期/存钱 → 首页/统计/我的管理接入 → 平台组件/提醒及其它本地设置 → 编译与功能测试 → 独立最终 review。不能以“视觉先搭占位页”作为非受限能力的最终完成态。

## 8. 核对与最终验收要求

- **视觉**：同一账本同样例数据比对五 Tab、计算器、支出/收入/转账、流水、账户详情、预算、借还、存钱、我的。对照 p381/p394/p105/p292/p300/p008/p010 的布局，不仅换配色。深色、360dp 宽、200% 字体、系统 inset、键盘遮挡另列检查。
- **导航**：五 Tab 往返保留滚动；统计/账户/日历/对象筛选下钻后的返回来源正确；保存/再记/取消不清除错误的上下文；我的点击与 Debug 长按分别可用。
- **账务**：现金 1000、支出 12.34、收入 100、现金→储蓄 20 后账户与净资产一致；未入账 1 不扣账户但统计/预算按确认契约反映；借入/还款/借出/报销不变普通消费；无账户存钱只改计划。数据样例由测试生成，不使用用户真实账单。
- **现有能力**：OCR 从我的/编辑器均能到本地选图；结果必须确认，去重/失败/取消不写数据；应用锁前后台和文件选择返回仍正确；JSON/加密备份导出和恢复真实可用；回收站/保护副本/Debug 五工具仍可达。
- **数据契约**：新增字段经历本地保存、编辑、删除/恢复、完整备份、旧版本备份迁移、数据代际切换与查询更新；占位不写虚假实体或 preference。
- **验证口径**：当前仅完成源码与参考截图审计。后续报告分别给出共享测试、Android 编译、安装启动、设备交互的实际结果；编译成功不代表与薄荷交互一致。最终 review 需追查数据写入/更新/回读，不仅检查 Compose 外观。

当前最重要风险是业务面远超纯 UI 改版：现有代码没有账户、转账、联系人、项目/商家/标签、周期和存钱模型。以当前 `LedgerState` 直接堆入口或卡片无法完成用户要求；必须把真实数据契约作为页面实现的前置条件。

## 9. 总方案已选契约的审计补充

总集成于本次审计期间确定：**保留旧 Entry / Category 线格式，新增同事务 EntryDetails、EntryTag、AccountTransfer 等实体，通过统一 FinancialActivity 投影整合普通收支/转账**。本审计接受这个方向，矩阵内“扩展交易字段”具体落到新伴随实体，不要求改写旧 Entry 的字段格式。

- `EntryForm` 展示/修改的账户、项目、商家、标签、入账/对账/预算属性，从伴随实体组装 `EditorDraft` 并以一个命令原子提交；不能先存 Entry 再异步存 EntryDetails。
- Home 最近交易、账户流水、全局流水、联系人/计划详情共用 `FinancialActivity` 行投影，使用稳定的活动类型+来源 ID 作为 key。转账不能临时伪造 `EntryKind.INCOME` 或 `EXPENSE`。
- 当前 `EntryPagingCoordinator` 的 cursor 只按 Entry 的 occurrence/id，需要对应统一活动分页契约；不能把第一批 Entry 与第一批 transfer 在 UI 排序后当作全量有序分页。
- Category 线格式保留不代表转账分类能放进 Direction.EXPENSE；转账分类的本地实体/类型契约必须明确，选择器不能把两者混在一个虚假“支出分类”集合。
- 旧备份无伴随记录时应归一为明确的旧语义：无账户、已入账、未对账、计入预算、无关联对象；具体默认值由迁移契约确认。已经有伴随表但引用损坏时不可悄悄当旧数据吞掉。

## 11. 本轮 Widget 与 CSV 的价值和完成标准

**CSV 导入导出值得本轮实现，优先于装饰性的额外主页面板。** 用户要贴近免费功能，导入/导出是参考明确可达的本地入口，且 DawnYew 当前 `TemplateRegistry.kt:8` 的三种模板全部 `AWAITING_SPECIFICATION`，`TemplatePage()` 仅文案；已有 `Command.CommitImport` / `ImportPlan` / 去重预览框架，但 `MainActivity` 没有 CSV 选取/导入导出链路，不能宣称已有完整能力。

建议定义并保存文档化的 **DawnYew CSV v1**（含版本/固定列、稳定活动 ID、类型、发生时间、账本、金额/币种、分类、付款/收款账户、备注及关联对象），支持自己的文件往返；普通用户可选列映射并在预览中显式选目标账本/映射实体。格式不承担完整数据备份，完整迁移继续 JSON。新伴随数据和 transfer 不在现有 `ImportPlan` 内时，先扩原子导入契约，不能只导入旧 Entry 而静默丢账户或标签。已有 `platform/android/.../tabular/OoxmlCodec.kt` 是受限 xlsx codec，可复用统一行适配器接 xlsx；不能据此声称支持旧二进制 xls，亦不能凭猜测开放微信/支付宝模板。必须覆盖中文/逗号/引号/换行/BOM、金额范围/精度、非法日期、重复文件、公式前缀的表格安全、取消/锁定后的写入阻断。CSV 导出在选定完整查询范围上执行，不能导出当前已加载的 50 条当全量。

**本地桌面组件也值得本轮实现，但应在 FinancialActivity 与账户摘要稳定后独立推进。** 参考有 7 个未见预览入口 VIP 检查的类型：2×2 双金额、2×1 单金额、2×2 金额与次指标、4×1 金额+新增、3×1 金额、1×1 新增、4×2 柱图。它们可由 3 类 Android RemoteViews 家族（金额、快捷按钮、图表）参数化布局复用，再提供尺寸配置；不需要七套独立数据算法。另 3 个受限类型只留空占位。

Widget 真正完成需包括：manifest Provider、配置页/固定账本和期间、桌面添加、点击进入对应页/记账、提交与恢复后的更新、删除清理、进程重启后的刷新策略、无需联网。应用锁开启/锁定时桌面不能暴露金额，配置和显示均须遵守锁策略；绝不缓存明文敏感账单到 widget options。图表生成本地小图可以，不能用静态样例图假装实时账本。只做 10 张预览卡而无 Provider 不算本地组件完成；若本轮暂未完成任何非受限类型，应在总交付列为真实未完成项，不能改写为“会员占位”。
