## 方案审阅结论与可测约束

认可 route 的同页表单加可收起计算键盘方案，以下作为验收约束：

1. 360dp 常见宽度，普通新增首屏应同时出现类型、可编辑金额、分类快捷项、账户、标签及固定保存；初始不自动开启系统 IME。默认路径不能先进入独立金额页。
2. 类型区约32dp，金额区约56dp，分类三列两行约72dp；账户/日期与标签使用紧凑行，不再逐项堆叠带大 padding 的通用卡片。分类超出快捷容量仍能进入全部选择，当前选中项始终在快捷区可见。
3. 标签常显。项目、商家和较少使用的状态可放“更多”，但日期、备注、已入账、不计入预算、已对账、标签多选与维度新增都必须保留真实动作。只改变呈现，不改变命令模型或默认值。
4. 默认固定计算键盘约172dp、保存区约64dp；与正文合计目标约626dp。按 `BoxWithConstraints` 的实际 body 高度处理小窗口和大字体，提供常显收起入口，不能将正文压成零高度。
5. 系统 IME 与自定义数字键盘不能同时占位。正文仅一个滚动容器；保存区位于该滚动容器之外，并随 IME 上移；避免 Scaffold padding 与表单重复消费系统底部 inset。
6. 按键和保存采用最小高度而不是裁字的固定高度。字号大于1.4时，分类可切两列、内容自然增高并允许滚动；不能以截断字段或丢操作换取首屏截图。
7. OCR 草稿的警告、重复核对失败重试、重复确认与金额等字段确认必须可达；主次保存使用相同完整 guard。编辑与退款保留已有字段、禁用分类/类型切换规则、退款预算继承规则及正确按钮文案。

## 验收证据清单

- 360dp 普通新增默认图：金额/分类/账户/标签/保存同时在可用页面内。
- 同页自定义键盘录入含小数及算式；分类切换、标签多选后金额不丢失；保存返回后账单内容正确。
- 系统 IME 与备注输入图：自定义键盘收起，保存可见；收起 IME 后表单及金额不丢失。
- 大字体与小窗口：标签/更多/保存可达，正文能滚动，无文字裁切和重复键盘。
- OCR 未确认/核对中/核对失败不得保存；确认后保存保持 OCR 元数据。
- 编辑账单与退款：保存修改/确认退款、日期/账户/标签/备注操作存在；退款无支出收入切换，既有预算资格不改变。
- 空分类/空标签/全部账本进入：提供真实选择或新增路径，不伪造默认对象。

## 成品源码交叉审阅

已读取 route 的 `EntryScreens.kt` 和 `EntryComposerControls.kt`。未发现仍需阻塞构建的 UI 源码问题，以下不等同于真机验收：

- 正文使用一个 `weight(1f)` 滚动列，计算键盘与保存区为其兄弟节点；仅表单外层调用一次 `imePadding`。按实际 body 高度、字号控制默认展开，OCR 默认收起，且保留显式展开/收起与系统输入入口。
- 首卡包含类型、金额与两行分类；第二卡包含账户、三个优先选中标签快捷项、全部标签、备注/时间和更多。按实际控件默认最小高度估算，普通正文约380dp，计算键盘及上间隔约176dp、保存区64dp，总计约620dp；此为源码尺寸预算，需设备图确认。
- 发现 Material3 点击版 `Surface` 会插入 `minimumInteractiveComponentSize`；本地 M3 1.9.0 `Surface.kt:219`、`InteractiveComponentSize.kt:102–118,196–198` 证明默认48dp会撑高32/36dp控件。route 已在 Chip/Row 组件内部独立使用 `LocalMinimumInteractiveComponentSize = Dp.Unspecified`，避免弹层或后续调用脱离表单 provider 后再次变大。
- 已核对全部 `EditorChange` 字段仍有入口：金额、备注、日期、时间、类型、账本、分类、识别确认、疑似重复确认、账户、已入账、预算排除、已对账、项目、商家、标签。新增维度仍走既有 `createEditorDimension` 回调，退款仍锁定类型/账本/分类并显示预算继承说明。
- 主次保存使用同一 `canSave`，保留 OCR 核对状态与确认约束；金额算式继续由既有 `AmountCalculator` 解析，显示键 `−`、`×`、`÷` 分别转为 `-`、`*`、`/`，不使用浮点金额计算。错误滚动已改为等待一帧再获取新的内容高度。
- 根 Scaffold 的 padding/inset 消费由 root 检查并处理；IME 与固定保存的实际关系仍须设备截图验证。
