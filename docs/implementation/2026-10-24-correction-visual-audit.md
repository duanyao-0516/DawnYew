## 已证实的根因

1. 信息层次和通用组件密度同时放大。`Theme.kt` 使用 Material 默认 `Typography()`，`FinanceComponents.kt` 用 22sp 的 titleLarge 作为卡片标题，主金额约 36sp、圆角 24dp、卡内 padding 18dp、通用列间距 12dp、标题行 minHeight 48dp。这些叠加使首屏信息量大幅下降，不能只修改一个行高解决。
2. 首页多出独立选月区、大标题及全月 31 点折线。参考只在紧凑月份支出卡内显示 7 日平滑面积图；参考首屏可见支出卡、未入账、最近 3 笔与预算开头，现状只容纳支出大卡和部分未入账。
3. 统计把摘要、主指标、分类行、按钮全部堆进大环图卡。参考首屏可以看到分类环、日趋势、月度柱图三张卡以及配置入口；现状首屏基本只有一个分类卡。
4. `PanelDirectoryPage` 的 `SettingRow -> onOpen("配置$title")` 没有开关，没有显隐状态，不等价于参考配置页。参考配置行右侧是真实 SwitchCompat。
5. 在线身份、会员、共享/日志/活动/客服等可见空入口违反本轮要求。不能把移除空正文或文案说明当作修复，入口本身须移除。

### 图表并非固定160dp

`jadx/sources/melandru/lonicera/widget/StatChartView.java:494–529` 实际计算 `height = measuredWidth * ratio`：

- PIE：0.48。
- LINE：0.28，并关闭 X axis line。
- BAR：0.40。
- RADAR：0.80。

默认统计卡图表宽 912px：环图高437px、日趋势高255px、月柱高364px，恰好对应这些比例。按当前 density=3，图表区约145.7/85/121.3dp。首页图表区宽936px、高262px，同样是0.28。**应使用 chartWidth/aspectRatio，而不是全卡固定高度**，以兼容更宽屏幕和不同字体。

`StatChartView.java:480–487` 折线使用 `HORIZONTAL_BEZIER`、2dp 线宽、无常驻点/值；`SimpleStatView.java:60–62` 开启面积填充与 Y 标签。`StatChartView.java:648–658` 环图 holeRadius75%、rotation45°、隐藏默认 entry labels，标签由自定义 renderer 绘制。

首页 `home_panel_month_expense.xml`：上下16dp，标题11sp，标题与金额间距4dp，金额26sp，趋势左右8dp。统计 `customstat_panel_simple_view.xml`：上下16dp，标题15sp，摘要10sp，摘要上间距2dp、图表上间距4dp、图表左右12dp。默认三卡不应附加完整明细表和多个操作按钮。

## 修复规格

### 首页

- 顶部只保留账本标题、搜索等真正可用动作，去掉 AI 与独立的大月份行。月份在支出卡标题中，筛选放详情。
- 支出卡按参考组织：11sp 月份，26sp 金额，右侧紧凑收入/结余，7个完整日期标签，粉色2dp平滑曲线与向下衰减渐变。默认无圆点、无3条重网格，首页不画Y轴标签。
- 7日窗口以当前日期为中心；历史月份窗口必须属于该月并贴合最后有数据日或月末。数据范围/精确总额由真实投影返回，不能为了形状伪造数值。窗内无记录为0，尚未发生的日期按已有未来日期语义区分。
- 未入账使用条件卡；最近交易紧凑两行，完整交易详情仍可点开。卡片首屏密度目标必须按相同fixture比较，不依赖手动缩放。
- 各面板开关控制实际 renderer 并持久化。无数据可呈现该业务空态与实际新增动作，但不得以同一个“暂无内容”占位代替实现。

### 统计

- 主页面直接开始三张摘要卡，不重复账本/月选择器大块。所有详情各自承载范围和口径筛选。
- 分类卡：青绿主色、75%内孔、45°起始角，外部标签引导线，中心使用小灰色总额；图表区宽高比0.48。退款不产生负扇区；退款与净额精确值在摘要/详情说明。
- 日趋势：同一面积曲线 primitives，主卡可有紧凑Y轴标签，宽高比0.28。
- 月度：粉色圆角柱，X/Y轴明确，宽高比0.40。不通过巨柱/巨大金额强行填满卡。
- 首页/统计共用图表实现，数据与视觉配置分离。每张统计卡点击进入完整详情：标题、范围、口径、图、完整数据行、总计/数值和真实可核对下钻。不把所有内容堆在概览，不把“配置卡名”转成空二级路由。
- 对比、维度和时间面板采用适当条/线/环图，不把16类全画成同一饼图。多标签统计明确可重复归属，不能将标签总和宣称总支出。

### 更多、我的与底栏

- 更多保持两列，每块约84dp，36dp图标、15sp名、11sp说明、16dp块间距；首屏完整显示8个功能块。标题18sp居中，不附账本副标题。
- 我的删除整块身份和会员区域。保留离线统计摘要、真实管理入口与52dp设置行；未实现的共享、在线日志/活动/客服/评分/推广等直接无入口。
- 底栏采用紧凑图标选中态，不加 Material3 巨大 pill 与可视标签；保留 contentDescription 和足够点击目标。财务账户仍代表现金/银行卡/借还数据。

### 二级页完整性

以下应为可滚动完整内容页，不是塞进整列 AlertDialog：统计详情、资金账户详情/余额历史、借入借出及报销详情、周期计划与执行记录、存钱计划与流水、交易详情与关联退款。页面具备明确标题、摘要、记录区域、编辑/执行/归还/退款等实际适用操作。新增/简单编辑仍可使用合理大小表单或弹层；复杂字段过多时使用表单页。

同一业务无数据时显示对应空态是完整状态；只有标题/返回/空Box或提示“功能未实现”不是完整页。每个可见入口必须在验收表中有实际目标和操作证据。

## 可复用绘图实现建议

限定在 finance UI 内新增紧凑 tokens/图表组件，不修改无关平台/存储策略：

1. `FinanceAreaChart` 接受有序日期值、颜色、是否显示Y标签、可选点击回调；Canvas Path 使用相邻点的水平中点作为 cubic controls，对齐 HORIZONTAL_BEZIER。路径闭合到零基线再用 Brush.verticalGradient 填充；负值/退款须由明确统计口径处理。绘图只做坐标归一化，金额仍用Long汇总、格式化。
2. `FinanceDonutChart` 接受非负扇区金额与标签；按总额计算角度，默认内孔75%，紧凑中心文字，左右外部引导标签避碰。大量小类别合并仅属于视觉展示，详情保留全量且需显示“其他”汇总真实值。
3. `FinanceBarChart` 接受时间/维度与值，绘制圆角柱与基线，0不伪造高度；正负混合时共享零轴。按0.40比例布局。
4. `FinancePanelCard` 单独明确 header/subtitle/chart 的间距，不沿用统一 spacedBy(12dp)。不把卡的可见标题高度强行设48dp；整个header可承担触摸目标。
5. 配置页 `PanelLayout` 稳定ID+顺序+enabled 控制，Toggle直接保存，长按拖动触发邻项让位，松手吸附并直接保存；标题点击仅在存在真正编辑器时显示可点击语义。

## 实施追加：最新排序要求与交叉审阅处理
