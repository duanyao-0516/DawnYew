# 全局悬浮记账：实现与验证

日期：2026-10-25。分支：`p/duanyao.0516/codex/dawnyew-android-app`。当前工作区交付，未提交推送。

## 用户可用流程

自动记账页开启“显示悬浮球”，依次检查结果通知与系统无障碍截图授权。授权后服务通过 `TYPE_ACCESSIBILITY_OVERLAY` 在其他 App 上显示可拖动吸边的悬浮球。点击隐藏自身，等待显示帧后截图；本机 OCR 识别金额与正负号，直接记账。打开“保存前确认一次”后出现可编辑金额、收支、账本、分类、时间、备注的全局面板。成功通知支持查看、修改、撤销。

无明确金额/方向会要求补全，不根据支付渠道或商家文案拒绝。缺日期使用截图时间，默认选择在备注留痕。截图只在内存处理，不联网、不写入相册。保存结果通过原子事务与回执核验；撤销保护创建操作、版本、来源和关联退款。

应用锁开启时不会扩大账本授权：短时内存请求通过通知进入正常解锁流程，最长两分钟，进程退出即失效。关闭开关、服务解绑、息屏、数据代际变化会取消未提交请求。受保护屏幕返回系统截图失败，不伪造截图结果。

## 交叉审阅修复

- Activity 构造阶段读取配置导致启动 NPE：改为 lazy，实际设备复测通过。
- 默认值来源被预览抹平、解锁后重复确认：保留来源信息；已经确认的请求恢复后直接提交。
- R8 修改命令类名导致回执核对失败：新截图命令采用稳定回执名称，Release R8 构建通过。
- 同 datasetId 恢复备份的竞态：通过 `GenerationRepository.inGeneration` 在写入及回执 mutex 内核对调用者 epoch。
- 待解锁通知与内存寿命不一致：系统通知 TTL、单个待处理请求、替换清理与投递失败回收。
- 服务解绑残留请求、排队撤销期间锁屏：补齐连接、屏幕、会话和代际校验。
- 通知权限撤销竞态：发送失败不会把已提交账单误报成未保存；通过 Toast 告知结果。
- 无可用分类的确认面板：交给领域事务原子补建截图分类。

设备用另一个 UID 的本地 fixture 展示用户提供的两张私有截图，实际触发系统截图和生产 OCR，没有把金额或 OCR 结果直接注入保存逻辑。

设备测试实际验证：

1. 从功能开关显示授权用途说明，再进入系统无障碍设置。
2. 外部 App（fixture UID 10153，DawnYew UID 10150）上真实截图识别支出 1.98，后台入账与结果通知。
3. 使用通知真实 PendingIntent 撤销；稳定相同画面再次截屏不复活回收站账单。
4. 切到系统 Settings，悬浮窗口仍然存在。
5. 外部 App 截图识别 35.50，全局确认改为 36.50 后才入账。
6. 用独立存储实例重新打开磁盘，保存结果一致。
7. 修改已保存账单后，旧通知撤销被拒绝，修改后账单保留。
8. 关闭功能后悬浮与确认窗口移除。

私有证据仅保存在 `.local/floating-device-test.log`、`.local/floating-device-evidence/` 和 `.local/floating-fixture/`，不入 Git。测试结束恢复隔离包原账本、配置与系统辅助设置；没有覆盖正式应用。

## 验证边界

- 首轮“相同页面”测试中系统提示/通知改变了实际像素，产生不同指纹。测试待画面稳定后通过；去重契约是相同截图指纹，不是“金额相同即同一账单”。未放宽生产规则以通过测试。
- 磁盘重开验证不等于杀进程重启验证。尚未执行 OEM 真机、API 30、真实生物识别解锁接续及通知运行时首次弹窗的完整矩阵；这些分支完成源码审查，不能据此声称全部设备已验证。
- Release 完成编译及混淆，运行验收使用隔离 Debug 包；发布版未进行设备安装验收。
