## 1. 范围与离线约束

- 保持无登录、无会员、无云服务、无运行时网络权限；已有本地应用锁、加密备份、离线 OCR 保留。
- 原先误保留的登录、会员、消息、AI、同步等空入口已移除，不以只有入口的页面表示功能完成。
- 资金账户是本地账务模型，支持收支与转账，不是登录账号。没有本地业务模型的分期、多人协作、信用卡账单周期等能力不提供空壳入口。
- 以实际采集页面、可达功能和反编译资源为参考；保留 34 个唯一参考图片文件、40 项用途的来源与 SHA 清单。Android 使用对应资源，JVM 使用平台适配。完整 APK、反编译源码及研究缓存不进入 Git。
- 本轮 UI 与能力落地针对 Android。共享 Kotlin 模块不等于已经交付或验证 iOS/Harmony 应用。

## 2. 离线财务功能

| 范围 | 本次落地内容 |
|---|---|
| 资金账户 | 现金、银行卡、信用卡、电子钱包、投资、应收、应付、预付八类；期初余额/时间、归档/隐藏、资产统计和真实历史流水。 |
| 账单扩展 | 关联账户、项目、商家、多标签、未入账、不计预算、对账标记；保留关联退款和编辑、删除、恢复的原校验链。 |
| 转账与往来 | 显式转出/转入端；借入、借出、报销、联系人、本金与结算。单据虚拟账户只允许所属业务命令写入，余额由交易推导。 |
| 周期交易 | 日、周、双周、月、年、季度、工作日、周末八种频率；有限/持续、暂停、跳过、归档、执行凭证与关联流水；前台批量上限100期，超过上限显式继续。 |
| 预算 | 月总预算、分类额度、额度转移和撤回；退款预算资格动态依据父支出，预算用量与普通收支统计分开。 |
| 存钱 | 挑战、梦想、目标、随手攒钱四场景；存取记录、愿望完成/取消及可选真实账户转账，进度与资金余额不混用。 |
| 统一流水 | 收支、退款与转账共用分页和汇总；按账本、日期、分类、账户、项目、商家、标签、金额、文本及记录状态筛选。 |
| 文件与快捷入口 | DawnYew CSV 收入/支出交换、导入预览/重复与冲突处理、批次撤销；静态桌面快捷组件；完整 JSON 与加密备份继续覆盖全部财务模型。 |

CSV 不冒充完整备份；微信、支付宝和 DawnYew Excel 的具体模板适配仍需样本。提醒页展示本地到期/未结清项目，不宣称已实现每日后台通知调度。周期自动处理在授权前台工作，不宣称系统后台定时运行。

## 3. 数据、存储与架构

- `shared/core` 承担财务规则、金额、引用关系、账户历史、面板聚合和原子重排；金额使用整数分。
- `shared/storage` 加入财务表、约束、索引与 Room schema 4，扩展真实 SQL 流水、汇总、历史和面板查询；旧数据经迁移进入同一仓库，不另建 UI 假账本。
- `shared/protocol` 的 JSON 备份升级为 v2，覆盖23类实体，兼容旧 v1 九类实体；源版本/counts/digest 与补齐后的候选计数分离，保留严格 schema 校验、流式暂存、取消清理和原子恢复。加密封装版本不随业务实体扩展随意改变。
- `shared/presentation` 集中草稿、导航、查询、面板、周期执行与提交状态；异步结果继续匹配 scope、dataset、contentVersion 和授权/数据库 epoch，写入保留幂等回执与恢复流程。
- UI 不复制金额/备注业务值。`EntryComposerState` 仅拥有输入模式、焦点、选区和组合输入状态；`EditorDraft` 是账单事实来源。
- 通用二级列表收敛到 `SettingsSection` / `SettingItem`，拖动管理行收敛到 `ReorderSettingRow`，日期范围通过明确的 presentation 函数区分全局范围、自然月业务和日历月份。
- 删除被替代的旧金额前置页、旧首页、旧流水/统计/回收页及旧筛选 Dialog，减少并行实现。

## 4. UI 与当天反馈修正

| 用户反馈 | 最终代码调整 |
|---|---|
| 首页/统计面板只有入口，未实际开关 | 首页10类、统计16类面板使用统一持久化布局；开关控制实际显示，顺序直接驱动首页。 |
| 排序是交换、动画重复 | 改为长按拖动插入、邻项让位、释放落槽；当前拖动项避免叠加 placement 动画；失败或取消恢复真实位置。 |
| 管理页风格不统一 | 面板、分类、账本、项目/商家/标签等共用管理行与拖动交互；不为没有启用概念的模型增加虚假开关。 |
| 开关导致其他行闪灰 | 区分业务不可用与暂时提交锁，写入期间保留禁用交互，但不把整组开关改成禁用颜色。 |
| 设置返回跳到顶部 | 按页面保存实际列表位置，返回恢复原 index/offset；新测试要求小窗口中先发生真实滚动。 |
| 记账页风格割裂、步骤过多 | 金额、分类、账户、标签、备注与保存放到同一页，紧凑布局；小窗口/大字体等保留必要滚动。 |
| 输入17只剩7 | 修正局部函数引用缓存旧草稿的回调问题，最新 bindings 驱动连续输入；保留小数、退格、表达式计算与继续记账。 |
| 点击金额不能唤起键盘 | 金额点击请求自定义计算键盘；备注获得焦点切系统文本 IME，避免两套键盘重叠。 |
| 日期时间位置、备注 Dialog | 日期/时间移到金额右侧；备注页内最多三行，超出内部滚动，保留中文组合输入选区，不使用备注弹框。 |
| 首页只显示七天、无法自定义范围 | 图表保留完整选择区间，只减少轴标签密度；整月包含首尾，自定义日期贯穿查询、下钻和恢复。 |
| 日历数字被顶起、显示笔数 | 固定日期基线，第二行显示收入 + 退款 - 支出的净额，不把转账混入收支。 |
| 普通二级页圆角卡片过多 | 备份、导入导出、设置、提醒、安全、组件、手册、货币、自动等改为平面分组列表。 |
| 搜索筛选未参考原版 | 紧凑搜索框/筛选条与结果汇总；待选草稿和已应用查询分离，取消不影响结果，清空后仍需应用。 |
| 流水密度过大 | 去除重复卡片内边距，普通交易统一两行约61dp，大字体允许自然增高。 |

整体审查还修复了：自定义范围下“更多”预算摘要月份错配；从首页账户追踪进入账户后切账本无效；恢复页面时预算槽无条件重复读取。主Tab与详情来源范围分别管理。

## 5. 三种截图记账入口

1. **系统截图监听：**用户主动启用前台服务，只查询启用后新增、已提交且符合截图来源条件的图片；完整媒体权限和通知能力必须可用。查询、去重与识别次数有界，未授权时不读取图片元数据，锁屏清理待领结果。
2. **状态栏截屏快捷按钮：**提供 Quick Settings Tile，每次通过系统 MediaProjection 同意完成一次捕获；透明授权页、一次 VirtualDisplay、超时/取消/锁屏清理，不复用授权 Intent，不绕过 FLAG_SECURE。
3. **分享图片与本地选图：**继续使用本地 URI 输入，和前两种入口共用离线 OCR/解析器及人工确认草稿。

`CapturePlatform` 将共享 UI 与 Android 实现隔离；`CaptureRecognizer` 统一解析；进程内 `CaptureInbox` 使用有界、用途/数据库代际绑定、短TTL、单次消费 token。截图不自动写账，最终仍须核对并保存。监听结果通过本地通知交付，不宣称所有 OEM 都可无交互弹出。

审查发现并修复锁屏/取消期间像素复制仍投递、并发新请求被静默忽略、通知渠道单独关闭仍启动监听、外部伪造自动启用extra、结果发布异常不能终结等问题。分别通过请求终态、原子失效边界、每请求结果、实际通知能力和一次性动作 token 收敛。
