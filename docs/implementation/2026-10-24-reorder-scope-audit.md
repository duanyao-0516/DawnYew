# 2026-10-24 长按拖动排序范围审计

用户本次明确要求：调整顺序统一使用长按拖动，邻项挤位，松手吸附；主页面板顺序实时反映首页。此要求替代纠正初稿里“至少提供上移/下移”的降级设计。

## 已有可见排序入口

| 页面 | 当前代码/真实语义 | 处置 |
| --- | --- | --- |

| 账本管理 | “置顶”调用 UpdateLedger，将 sortOrder 设为当前最小值-1 | 不是固定置顶业务：Ledger 没有 pinned 字段。删除按钮，改全账本列表长按拖动+一次原子重排 |
| 分类管理 | “置顶”调用 SaveCategory，将同账本/方向最小 sortOrder-1 | 不是独立置顶业务。删除按钮，改同账本/收支方向完整分类顺序的长按拖动 |
| 项目 / 商家 / 标签 | “置顶”调用 SaveDimension，将当前可见项最小 sortOrder-1 | 同样只是排序捷径。删除按钮；每个账本+DimensionKind 独立长按拖动，归档隐藏项不丢失 |
| 账户 | 当前无可见排序控制，但模型有 sortOrder；参考账户页明确提示长按/拖动 | 在原类型分组内长按拖动，保留现金/储蓄卡等分组，不跨类型误换位；不能嵌套多个竖向 LazyColumn |

全局搜索所有 UI `置顶/排序/上移/下移/sortOrder` 后，**没有独立 pinned 状态或固定置顶业务入口**。不保留上述“置顶”作为另一套排序交互。

## 不应当变成手动拖拽的操作

- “移动到账本”改变账单所属账本/分类，是财务归属迁移，不是顺序调整。
- 流水按发生时间/金额、商家按常用/金额/名称/最近的排序方式属于计算出的排序规则；参考有这种菜单，不能把规则选择误改为任意拖动财务历史。当前产品未暴露这些完整规则菜单，不以此次修复宣称已完成。
- 预算额度调配、存钱支取、记录删除/恢复均为真实业务写入，不属于列表顺序。

## 原子写入及隐藏项契约

领域层新增每类原子 reorder 命令，逐条 Save/Update 循环不构成原子重排。提交必须校验 ID 无重复、属于正确 scope、完整成员一致及必要版本约束；成功后一次性更换 order/revision，失败不留下前半已改后半未改的状态。

- Ledger：全部账本（包含归档）。
- Category：指定 ledgerId + direction 的全部分类（包含停用）。
- Dimension：指定 ledgerId + kind 的全部对象（包含当前隐藏的归档项）。
- Account：指定账本范围的完整账户集合（包含 hidden/archived/业务专属资金账户）；交互只允许同类型内改变可见项顺序。

当 UI 隐藏归档/隐藏账户时，拖动返回的可见 ID 先按原来完整序列的可见槽位回填：隐藏项仍留原槽，不能把不可见对象从命令中漏掉，也不能把用户在一个类型中的动作扩展到其他类型。

共享组件提供整个 LazyColumn、header/footer、稳定 key、拖起浮层/挤位/吸附动画；账户使用平铺的分组标题和账户项，分组标题不可拖，账户只能在相同类型组中交换。一次松手仅提交一次完整顺序。持久失败后展示已提交的外部序列，不保留虚假成功状态。

实现已接入共享 LongPressReorderableList：面板由visual负责，账本/分类/维度/账户由route/detail作者负责。账户进一步按 ledgerId+type 分组，跨账本也不混拖；参考中的类型分组保留为不可拖标题。隐藏合并 helper 位于 VisibleOrder.kt，完整命令接口见 atomic-reorder-api.md。UI全局已无“置顶/上移/下移”按钮。领域与拖拽组件已经交叉源码审阅，实际手势与重启/恢复验证由root记录。
