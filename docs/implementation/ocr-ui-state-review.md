# OCR 草稿、共享 UI 与统计复核

日期：2026-10-18。此记录区分 JVM 证据和仍需实际界面验证的事项。

## 已修复的边界

- `AppController.editor` 持有完整 `EditorDraft`：金额、时间、备注、分类、实际账本、编辑目标/revision、退款父项、OCR 来源、确认状态和 operationId。全部只在进程内；没有草稿 SavedStateHandle、Bundle 或磁盘序列化。新 OCR 草稿整体替换，获得新 operationId 且 confirmed=false。输入变化重新要求 OCR 确认。
- Application 继续持有 Controller，所以 Activity 旋转重建从同一个 StateFlow 恢复完整草稿；新进程 Controller 从空草稿启动。编辑/退款身份不再由局部 remember 对象与独立可保存字段拼接。
- 疑似重复通过 repository 的有界 SQL 存在性查询检查同图和同日同额（含回收站提示），不扫描全量 entries。检查未完成/失败不可保存，可重试；命中后单独勾选“仍要保留”，不会自动删候选或禁止合法重复。金额/日期修改后重新检查。继续保留的确认记录在进程内 EditorDraft，保存仍经正式 SaveEntry 与操作回执；未新增永久账单字段。
- UI 仅发送 `EditorChange` 单字段事件及 operationId，控制器从最新状态原子合并；旧 Compose 快照不能回写重复检查的 pending/error/result，也不能覆盖同帧其他字段。金额/日期更新会开始新检查，检查期间拒绝过期确认点击。
- 保存失败保留输入；同一草稿重试复用 operationId；成功后清除或为“保存并继续”创建新身份，并保留仍有效的收支类型、分类和实际账本，清空金额/备注。旧保存回调不清除后来创建的 OCR 草稿。最终事务幂等仍由 repository/领域回执执行。
- “全部账本”入口不能隐式把新账单存到第一本，必须选择实际账本。未保存草稿的界面返回会确认放弃；系统返回通过 Activity 传入的回调执行同一流程。
- 明细/统计各自保留 QueryScope；统计下钻只缩小原范围，不丢分类/备注/类型条件，不把部分月扩成整月。类别原始支出与退款明细分别有入口；零原始支出不出现支出入口，退款筛选只能继续下钻退款，任何种类/分类/账本下钻都不能扩大原筛选。返回下钻前的统计页恢复原范围，明细原范围也保留。
- 首次 dataset 装载恢复有效的 `lastLedgerId` 和 `lastPeriod`，失效/归档账本回退首个可用账本，缺失月份使用本机当前月。只有用户显式切换账本/期间才排队写偏好，等待普通保存和结果确认完成后串行执行，连续选择合并为最新值。统计查询/下钻不写偏好；“全部账本”只保留在本进程。`lastPeriod` 沿用 `YYYY-MM`，记忆选中范围的起始月份，不序列化备注/筛选/草稿。恢复或清空会撤销旧偏好队列并应用新 dataset 的偏好。
- 普通命令 `onSuccess` 完成后才调用 `acknowledgeOperation`；确认落盘结束前持续 busy。回调或确认失败保留已提交状态，不误报事务失败。启动恢复通过常驻对话框区分“已提交”与“未确认提交”，用户明确确认后才清除最小 operationId 标记；未确认时阻止不同 operationId 覆盖，同 ID 可重试。已提交的同 ID 草稿在显式确认后清理。标记本身由 Android GenerationRepository 落盘，不保存敏感草稿。
- 异步统计区分 Loading/Content/Error，汇总及结余溢出明确报错，不显示为“0 元/暂无数据”。预算写入正在展示的月份，失败不关闭输入框；年度箭头移动整年。
- 收入和净支出同时绘制、带图例和等价数据表；摘要显示收入/原始支出/退款/净支出/结余。分类原始支出分母不含退款，同时显示退款/净额并保留退款独有类别；账本有净支出柱图及原始支出/退款/净额文字。
- 将来日期无记录时断开趋势；存在真实记录时展示并提示日期异常。比例文本采用整数长除法、两位小数、四舍五入；Float 仅用于绘图坐标。
- 主题 secondaryContainer 采用 teal neutral；摘要/分类数值改为可换行布局，列表金额独占一行以适应小屏大字体。密码字段禁自动纠错并使用 Password 键盘；Android 窗口安全由 Activity 实现。
- 恢复保护副本入口调用 `PlatformActions.restoreProtectionBackup()`；认证和执行由 Android 层提供。成功恢复/清空须调用 `resetTransientState()` 清旧草稿、导航与分页缓存。

## 设备/交互验收清单

这些步骤未由本 agent 执行，不与 JVM 测试混为一谈：

1. 360dp、200% 字号、横屏、键盘打开：录入、OCR 确认、摘要、筛选、密码、预算的字段和主按钮可滚动到达；无金额遮挡或文字裁切。
2. 手工输入与 OCR 草稿分别旋转：全部字段、编辑/退款目标、来源和确认状态一致；进程死亡后不恢复敏感草稿。锁屏后遮罩，解锁只恢复当前进程允许保留的草稿。
3. 系统返回与顶部返回：有更改时都提示放弃；取消提示保留所有内容，确认后清草稿。保存进行中不误报放弃或重复提交。
4. 连点保存、保存失败后重试、保存回调期间创建新草稿：数据库一笔，来源正确；旧回调不覆盖新任务。
5. 筛选餐饮和 2026-01-15..04-20，点击一月：仍为餐饮，范围 1/15..1/31；返回恢复原统计范围和滚动位置。分类/退款/账本下钻金额与同一聚合快照相符。
6. 自定义完整四月后设置预算：只修改四月；切换年度后箭头跳上一年/下一年。失败后输入保留。
7. 同期包含收入、支出、退款、退款独有分类、负净支出：两条线和数据表一致；五项摘要公式正确；类别比例不把退款计入分母，账本柱图有负方向。
8. 加载多于两页明细，翻页间插入/恢复数据：旧游标冲突后重取，不出现重复项；进入详情或统计后返回，范围与已加载页符合版本规则。
9. 统计人为超出整数汇总范围：显示错误；不出现零账本。设备时区变化使真实记录日期晚于今天时仍可见，并有日期异常提示。
10. 同图、同日同额和回收站命中分别检查，提示只做核对；未确认继续时不能保存，确认后允许创建另一笔合法消费。修改金额/日期会重查；失败重试保留草稿。
11. 保存并继续：选择非默认分类及收入账本，保存后仍保留有效选择，金额/备注清空；操作 ID 必须变更。
12. 提交完成、界面确认前杀进程：重启出现明确提交结果且不自动消失；确认后才能发起另一操作。未提交标记显示未确认提交，确认失败仍保留提示。
13. 切换实际账本和月份后重启恢复；选择全部账本不写非法 ID；保存过程中快速切换月份不覆盖账单 operationId；恢复备份后应用新偏好。
14. TalkBack：图例/金额含语义文字，可展开并逐行读取等价表，不仅依赖颜色。操作有可触达的触摸目标。

最终设备结果由主线程统一构建和验收记录补充；本记录不宣称 G2 OCR 准确率或 UI 设备验收已通过。
