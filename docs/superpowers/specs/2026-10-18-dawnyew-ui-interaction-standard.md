# DawnYew 交互与 UI 设计规范

版本：1.0。日期：2026 年 10 月 18 日。用途：首轮设计稿与交互原型的工作基线。

评审状态：用户已认可当前 UI 方向，可作为技术设计输入。批次 A 已交付并走查核心原型；批次 B、C 及尚未覆盖的 P0 操作状态继续按本规范完善，须在对应功能实现前完成关键交互设计。详见[首批交接](../../design/2026-10-18-dawnyew-figma-handoff.md)与[技术设计准入检查](2026-10-18-dawnyew-technical-design-readiness.md)。

采用 **Material 3 稳定组件与 Android Adaptive 布局**，以 WCAG 2.2 经 WCAG2ICT 解释后的相关要求作为可访问性检查依据，补充 Carbon 与 ONS 图表原则。未来 iOS 按 Apple HIG 适配系统交互。主视觉为青绿色操作色、中性背景、清晰金额层级；不并用多套视觉组件体系。

本规范依据[需求草案 v0.3](2026-10-18-dawnyew-requirements-design.md)。规范与工具的比较、来源和限制见[选型调研](../../research/2026-10-18-ui-standards-and-tools-research.md)。下文具体配色、间距、页面结构与动效时长是 DawnYew 的设计选择，不是 Material 强制规定。业务冲突以需求中的账务、离线和数据保护规则为准。

## 设计目标与优先顺序

优先级依次是：账目含义准确、录入与纠错顺畅、数据可迁移、内容易读、视觉一致。用户应随时知道当前账本、期间、金额含义，以及操作是否已经写入数据。

日常记账保持短路径，低频细节按需展开；用户必须决定的账本、金额与收支类型不能藏在次级页面。统计先回答“本月花多少、花在哪”，数据管理先回答“哪些记录会导入、哪里有问题、能否撤销”。

## 主体系与平台边界

| 层次 | 采用方式 |
| --- | --- |
| 组件和布局 | Material 3 稳定按钮、输入框、列表、导航、底部弹层和对话框；Android Adaptive 按实际窗口组织内容 |
| Expressive | 借鉴主次强调、分组和反馈原则；不依赖尚未稳定的新组件，不用持续形变装饰金额 |
| 品牌与语义 | 共享颜色角色、字号层级、账本术语、金额口径和任务流程 |
| 系统能力 | 返回、文件选择、系统认证、键盘、安全区域和辅助技术按平台适配 |
| 后续平台 | iOS 继续共享业务与主要页面，系统交互参照 HIG；桌面按可用空间扩展，HarmonyOS 排除 |

AndroidX 与 Compose Multiplatform 版本须在系统设计阶段分别核对；“采用 M3”不构成所有 Android 新组件都可直接用于 KMP 的承诺。[M3 发布说明](https://developer.android.com/jetpack/androidx/releases/compose-material3)、[平台支持](https://kotlinlang.org/docs/multiplatform/supported-platforms.html)

## 信息架构与导航

紧凑手机保留三个同级目的地：**明细、统计、设置**。三项均有图标及文字；切换时保留各页期间和筛选。“记一笔”是独立主操作，在明细和统计页使用带文字的显著按钮，不占导航目的地。

账本选择位于明细和统计页顶部，显示当前名称及展开提示。短列表用底部弹层切换，提供“管理账本”入口；不额外增加低频账本管理主导航。全部账本是统计或查询范围，从这里记账必须明确选择实际账本。

明细首页从上到下依次是账本与期间、紧凑收支摘要、按日流水、记账入口。统计首页依次为账本与期间、核心指标、趋势、分类分布、预算或账本比较。首页不出现资产余额、成员头像、登录注册、同步状态或付费入口。

设置包含数据管理、应用锁、账本与分类管理入口、外观、本地帮助及回收站。分类管理的权威入口仍随当前账本进入，避免设置中的快捷入口产生第二套配置。

## 尺寸与自适应

| 项目 | DawnYew 基线 |
| --- | --- |
| 设计参考画布 | 手机 390×844 逻辑尺寸；另验 360 宽、横屏与 200% 字号；大窗口参考 1024×768。画布不是固定运行分辨率 |
| 尺寸单位 | Android 间距与触控用 dp，字体用 sp；Figma 参考画布的数值按逻辑尺寸映射，不等于设备物理像素 |
| 间距档位 | 4、8、12、16、24、32；手机左右基础边距 16，区块间距 24 |
| 触控目标 | 至少 48×48dp，图标通常 24dp；触控扩展区域不能互相重叠 |
| 操作按钮 | 高频主按钮基准高度 48dp；随字号和内容增长，禁止截断标签 |
| 圆角 | 输入及小容器 12dp，内容卡片 16dp；浮层遵循所选稳定 M3 组件的形状 token；不把所有内容做成胶囊 |
| 分隔与层级 | 优先留白、分组标题和浅色容器；少量边线，避免每条流水都包一层带阴影卡片 |

布局按窗口宽度处理：<600dp 为紧凑，600–<840dp 为中等，≥840dp 可采用双栏；高度 <480dp 或键盘占位时回到适合可用高度的布局。大窗口通常使用侧边导航与“列表＋详情”，不要把手机列表等比拉宽。选中流水、筛选和输入内容在窗口变化时保持。

状态栏、系统导航和输入法区域由系统 inset 决定，不硬编码固定留白；主按钮不得被键盘遮挡。中等宽度是否双栏依内容和字号判断，不因设备被称为平板就强制双栏。[窗口尺寸](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)、[自适应导航](https://developer.android.com/develop/ui/compose/layouts/adaptive/build-adaptive-navigation)

## 字体与数字

优先使用系统中文无衬线字体；Figma 没有对应字体时使用 Noto Sans CJK SC 并记录替代，不能把替代字体当作真机一致性证明。数字在字体支持时使用等宽数字特性，金额列右对齐。字体随安装包或系统提供，不运行时下载。

| 角色 | 字号与行高 | 用途 |
| --- | --- | --- |
| headlineLarge | 32/40sp，Medium | 金额输入、单个关键合计 |
| titleLarge | 22/28sp，Regular 或 Medium | 页面标题 |
| titleMedium | 16/24sp，Medium | 区块标题、重要列表内容 |
| bodyLarge | 16/24sp，Regular | 流水主信息、字段值 |
| bodyMedium | 14/20sp，Regular | 日期、备注摘要、辅助说明 |
| labelLarge | 14/20sp，Medium | 按钮和选项 |
| labelSmall | 12/16sp，Medium | 少量辅助标签，不用于关键金额或错误说明 |

金额统一两位小数与币种说明；列表以类型文字和符号共同表达，例如“支出 −¥32.50”“退款 +¥18.00”。退款的加号表示流入，不把它命名为收入。净支出允许负值，按业务口径展示。

大数不省略为不可核对的“1.2万”，不对金额使用省略号；优先调整布局或换行，必要时提供完整金额明细。200% 字号下不缩小用户字体来维持原画面，表单可滚动、分类格子减少列数、摘要改竖排。

## 颜色与主题

默认跟随系统明暗主题，品牌主色固定为青绿；首版不启用壁纸动态色，以便验证稳定的账务语义与图表映射。以后引入动态色时，收入、支出、退款和危险操作角色仍需独立验证。

| 语义 token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| primary / onPrimary | #006A60 / #FFFFFF | #83D5C6 / #00382F | 主操作、选中态及其文字 |
| primaryContainer / onPrimaryContainer | #A4F2E4 / #00201B | #005047 / #A4F2E4 | 较弱强调容器 |
| surface / onSurface | #F7FAF8 / #18201D | #101512 / #DEE5E0 | 背景与正文 |
| surfaceContainer | #EBF1ED | #1C231F | 导航、分组容器 |
| onSurfaceVariant | #414944 | #BEC9C1 | 次级文字 |
| outline | #707973 | #89938C | 需要可识别的边界与状态 |
| income | #006B5E | #7ED9BE | 收入辅助标识 |
| expense | #9C4A0C | #FFB77D | 支出辅助标识 |
| refund | #7057A3 | #D2BBFF | 退款辅助标识 |
| error | #BA1A1A | #FFB4AB | 错误与危险操作，不表示普通支出 |

这是核心角色集，未列出的组件颜色沿用同一主题的 M3 语义角色；出图前补齐实际用到的角色，不在页面内随意新增相近色。类别配色与收支方向色分开：同一分类在同一账本的列表、图例和明细中保持稳定，不能随金额排序而换色。

采用 W3C 相对亮度算法计算，上述浅/深色 onPrimary 对 primary 为 6.50/7.65:1，正文对 surface 为 15.82/14.40:1，次级文字对 surfaceContainer 为 8.11/9.40:1；三种账务色对 surface 最低为 5.58:1，outline 对 surfaceContainer 最低为 3.93:1。这只证明所列不透明颜色对，透明度、叠层和实际图稿仍需检查。

所有常规文字目标至少 4.5:1；必要图形、控件边界与状态目标至少 3:1。分类色不足以形成清晰相邻边界时增加描边、间隔和文字标签。禁止只靠红绿或颜色表达收支、选中、错误。[M3 颜色角色](https://m3.material.io/styles/color/the-color-system)、[文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 组件使用规则

| 组件 | 采用方式 |
| --- | --- |
| 顶部栏 | 标题、当前账本、返回或少量页面操作；不同时塞入多行低频筛选 |
| 记一笔按钮 | 根页面可见，带文字标签；编辑页以“保存”为唯一主要提交操作 |
| 流水行 | 分类图标与名称、可选备注、时间、右对齐金额；整行可打开详情 |
| 输入框 | 持续可见标签、字段内或下方具体错误；占位文字不能替代标签 |
| 分类与类型选择 | 名称与选中标记并存；选中态不只改变颜色；收入与支出分类分开 |
| 底部弹层 | 账本、分类、短筛选等临时选择；高度不足可滚动或转完整页面 |
| 完整页面 | 金额录入、OCR 核对、文件导入与逐行纠错等有键盘或长流程的任务 |
| 对话框 | 丢弃已编辑内容、有关联数据的删除、永久清理、整体恢复等明确后果的确认 |
| Snackbar | 已落盘保存或可逆操作反馈；撤销快捷入口之外，回收站仍提供持久恢复路径 |
| 系统界面 | 文件选择、认证保持系统呈现；设计稿只画占位说明与成功/取消后的应用状态 |

滑动、长按或拖动可以作为快捷方式，但菜单或显式按钮必须提供等价操作。开发者与设计工具不得用一个整页位图替代可编辑组件。

## 核心任务流程

### 手动记账

明细或统计点击“记一笔”，打开完整页面，显示当前账本、支出/收入选择、大金额输入、分类及日期；备注按需展开。默认支出、当天，沿用明确的当前账本。首次未选分类时不给出伪造默认类别。

金额键盘与保存按钮在可触及区域，支持系统输入与辅助技术，不只支持自绘触摸键盘。非法金额直接解释原因；点击保存后防重复提交，写入失败留在原页并保留本次输入。成功后返回原上下文，提供“再记一笔”。返回时若有未保存修改，明确“继续编辑／放弃”。

### 图表复盘

默认当前账本当月，可切换年和自定义期间。顶部列收入、原始支出、退款、净支出和收支结余；以净支出作为支出分析的主数字，但不把它称为余额。各指标的口径可就地查看。

趋势使用折线或柱图；含负净支出时明确零线和负方向。分类比较优先横向条形图，展示非负的原始支出金额与占比；环图仅作补充，退款和净额在分类明细中分列。大量分类可收起次要项为“其他”，展开后必须能核对全部分类。

账本对比明确标题是原始支出或净支出，不混用口径；柱图以零为基线，不截断以夸大差异。图表下有等价数据表，精确数值不依赖长按或拖动才能获得。点击图项进入同范围明细，返回保留筛选。

预算仅在指定账本完整自然月且无类型/分类/备注筛选时出现。超过预算显示实际百分比及超支金额，进度条满格不掩盖超出部分。无预算和零数据有不同空态；“无记录”不等于已确认没有真实消费。[Carbon 坐标轴](https://www.carbondesignsystem.com/building-blocks/data-visualization/axes-and-labels)、[ONS 坐标轴](https://service-manual.ons.gov.uk/data-visualisation/guidance/axes-and-gridlines)

### 历史文件导入

流程为选择来源与文件、预览及映射、处理问题、确认导入、查看结果。来源同时包含微信、支付宝、DawnYew；未知模板明确不兼容，不靠用户手工改表掩盖尚未实现的平台支持。具体字段待用户提供模板，首轮稿只表现通用交互。

预览展示目标用途账本、时间范围、新增/重复/待处理/排除数量与合计；手机以摘要和可展开行项呈现，不把桌面宽表直接缩小。错误行包含原始值、问题字段与可采取的操作。确认按钮写清“导入 120 条”，未解决的所选记录不能提交。

提交期间禁止重复点击；用户取消或失败时保持原库。结果列明导入数量与批次，提供查看新增流水和符合条件时的批次撤销。来源身份和本地修改分别处理，重复、冲突与疑似重复使用不同文字和图标，不合并成笼统“异常”。

### 截图核对

系统分享或选择图片后，若已启用应用锁先认证；再展示识别过程、图片预览和可编辑字段。大窗口可并排图片与表单，手机采用可展开图片和表单。所有推测字段有“待核对”标记，金额歧义给候选值，不预填成看似确定。

草稿尚未入账时明确显示状态；确认按钮为“确认记账”。保存后才进入统计。识别失败可切换手动；取消清理应用临时副本但保留用户相册原图。首版稿不出现云端 AI、自动上传或语音已可用的入口。

### 数据导出和恢复

数据管理区分“完整备份 JSON／加密备份”和“导出流水 Excel”。展示范围、条数和保护方式。恢复整体替换要展示当前与待恢复库的摘要，明确覆盖后果与取消入口；不能用普通“确定”掩盖替换动作。

加密备份口令由用户输入；界面说明忘记无法找回。应用锁启用时按需求重新认证敏感操作。导出成功必须有文件写入成功结果，取消系统文件选择不显示成功。

### 应用锁与可逆操作

应用锁设置说明使用本机系统认证，无账号登录。系统提示由实际设备能力决定，设计稿不能假定所有 Android 都支持安全面容认证。失败、取消或暂时不可用保持遮盖；无可用认证方式不能显示已启用。

删除遵循需求中的影响范围确认与回收站规则，有关联退款时明确显示关联数量。撤销按完整删除组处理；不能只恢复一半。永久清理、清空数据、整体恢复用明确对象、数量和后果文案，并保留清晰取消操作。

## 状态 文案与反馈

| 状态 | 必须表达的内容 |
| --- | --- |
| 首次空账本 | 无记录、记一笔、导入历史账单；不塞示例流水充数 |
| 筛选无结果 | 当前筛选、清除筛选；不误导用户新建重复记录 |
| 本地处理 | 正在解析/识别/保存的真实阶段；可取消的操作提供取消，不编造百分比 |
| 字段错误 | 具体字段与纠正方式，如“金额最多保留两位小数” |
| 存储失败 | 未保存、保留输入、重试或释放空间；不先提示成功 |
| 识别不确定 | 待核对字段和候选项，不用装饰性置信度数字替代解释 |
| 认证失败 | 内容保持遮盖，提供实际可用的系统后备认证 |
| 不兼容文件 | 来源或格式未支持，现有数据未改变，可重新选文件 |
| 恢复失败 | 说明失败原因并保持原数据，不能跳到空首页冒充成功 |

文案使用“账本、流水、净支出、收支结余、完整恢复”等已定义术语；不使用“账户余额、登录成功、同步完成”等不属于本产品的概念。无网络是正常运行状态，不显示常驻离线错误横幅。

交互反馈使用稳定组件的状态与短过渡。自定义动效目标为 120–220ms，仅辅助状态变化；尊重系统减少动画设置，不延迟保存，不让金额滚动跳数。触觉反馈可选，不能作为成功的唯一信号。

## 首轮出图范围

首批按以下三组交付，共 12 类页面或任务组；每组包含必要状态，不是只交 12 张正常态截图。

| 批次 | 页面或任务组 | 必需状态 |
| --- | --- | --- |
| A 核心闭环 | 明细、记一笔、统计、账本选择与管理 | 正常、首次空态、金额错误、大字号、浅/深色；选账本→保存→列表→统计下钻可点击 |
| B 录入与纠错 | 流水详情与退款、截图核对、历史导入预览、导入纠错与结果 | 关联退款、识别歧义、重复/冲突、失败/取消、批次撤销条件 |
| C 数据与保护 | 设置与应用锁、备份导出、恢复预览、回收站与永久清理 | 认证失败/无能力、空间不足、错误口令、整体替换确认、删除组恢复冲突 |

1. 每页都能识别当前账本、期间或操作范围；无混入资产、登录、云同步和收费能力。

5. 导入、OCR、恢复、删除均有取消、错误、确认及结果状态；不可逆操作显示范围。
6. 设计稿保留真实文本、向量、组件、变量和布局关系；截图只能作预览附件。
