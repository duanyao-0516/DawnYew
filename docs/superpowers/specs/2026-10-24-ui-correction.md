# DawnYew UI 与功能纠正方案

## 纠正依据与本轮验收

用户已否定上一轮UI交付。上一轮“入口可达+空正文”“领域命令存在”“构建通过”不构成参考APP的功能或UI验收；旧报告保留作历史，不再作为当前完成依据。本方案优先于上一轮的“受限空页”“只做默认面板”范围。继续自主决策、不询问用户，修改当前工作树，保留既有数据和既有三处本地变更。

用户此段“账户/登录/会员”按其上下文理解为线上账号系统：删除登录、会员、账号、消息及所有在线服务入口；原参考五Tab中的资金账户继续用于现金/银行卡/转账/借还，不删除用户财务数据。所有可见入口必须有实际内容和可用行为，未实现项目直接不展示；不再挂空白页。

## 交互与功能

1. 我的：删除登录头、会员卡、共享、同步日志、活动、客服、评分、推广分享；首页删除AI入口；设置/备份移除自动同步、WebDAV；删除拆分/手续费、数字/手势密码、未实现组件预览、分期等假入口。保留真正可用的分类/项目/商家/标签/导入导出/账本/OCR/本地备份/设备锁/提醒/工具箱/回收站/设置/本地说明。
2. 面板配置是“标题+说明+右侧Switch”，开关即改变首页/统计内容，状态重启、备份恢复后保持；排序必须长按拖动、邻项让位、松手吸附并立即持久化，主页同步读取同一顺序。配置行不跳“配置XX”空路由。开关/排序用同一稳定ID配置，不依赖中文标题。
3. 首页提供现有数据能支持的10项面板：本月支出、最近交易、预算概览、预算追踪、账户追踪、分类涨跌、日历视图、收支对比、分类倾向、存钱计划。未入账保持条件面板。无信用卡账单周期实体的“账单概览”不显示，也不拿月收支假充账单周期。
4. 统计提供16项真实本地面板：分类统计、日趋势、月度收支、分类收支、年度统计、一周统计、账户统计、单笔最高、分类均价、笔数统计、周末统计、金额分布、项目统计、商家统计、标签统计、季度统计。“多人统计”不显示，因本地无作者/共享模型。参考的付费只是其商业限制，不是本地统计技术限制。
5. 每个统计面板能进入详情：范围、统计口径、完整数据行、数值、可核对的下钻。默认支出视图与参考一致；需要切类型/月份/年份的控件放在详情，不在每张主卡重复占高。图表不把退款画负扇区，不把转账算普通收支；标签允许多归属时须说明合计不可跨标签相加。
6. 账户/借入借出报销/周期/存钱详情改为真正的二级内容页：标题、摘要、记录、操作分组；编辑/新增可以用合理大小表单，详情不再装进一整列AlertDialog。资产趋势必须能查看真实历史余额，或不显示该按钮；本轮优先补历史余额和按日趋势。保留已有幂等、恢复、单据专属资金关系。
7. 全路由闭合：逐个可见按钮/行查目标，移除通用空白fallback。无数据应显示对应业务空态并能新增/筛选，不可显示虚构统计；不把空态当未实现页面。

## 视觉

按同设备1080×2373参考截图与本次采图做对应状态比较，不只用“类似绿色卡片”验收。参考关键证据 p381首页、p105统计、p025/p026首页配置、p121/p122统计配置，以及对应业务详情。

- 缩小Material默认排版：正文约15sp、辅助11sp、标题层次按参考；列表行/卡内边距按XML及截图量化。保持可点区域和大字自然增长，不使用固定高度裁字。
- 首页取消独立巨大选月区，将月份并入支出卡标题；卡片按参考约176dp量级组织，7天窗口的平滑粉色渐变面积图、完整日期标签，无无意义全月31点/网格。当天±3天窗口遇选中历史月时按实际数据/月底边界保持明确。
- 统计首屏目标：默认3张图卡可见，分类青绿环图带引导线/标签，日趋势面积曲线，月度粉色圆角柱图及轴标签。详情再呈现完整表格和精确值。
- 更多两列紧凑功能块；底栏参考图标式选中态，避免额外大块标签/指示背景挤压；线上账号区域完全移除。
- 开关目录同参考的卡片行，长说明自然换行；数量显示真实可配置项数，不声称11/17但只有10/16。

## 架构与数据契约

复用UserPreference持久化两个面板布局键，统一规范解析器验证稳定ID、完整顺序、去重/未知值/启用集合；旧备份缺键只在读取端给默认，不能修改旧源摘要。Domain命令、全量校验、批量恢复校验同步。已有Room表和备份实体无需新增版本。

聚合归属core/reference + storage范围受限SQL + repository接口 + GenerationRepository授权代理；不得使用生产StatisticsSnapshot.entries（生产SQL有意返回空列表），不得用首页3条或分页50条计算总量，也不得在Compose内扫描全库。聚合结果绑定request/dataset/version，后台/恢复/清空废弃过期结果，多个面板互不覆盖。具体冻结API见panel architecture审计与随后接口文档。

下钻须与显示值匹配：ActivityScope增加ISO weekdays与未分配账户/项目/商家/标签过滤，core、SQL、游标冻结和校验同步；不能把“星期一”或“无项目”点进全部流水。账户历史按openingAt、已入账普通交易和转账计算截止日余额，不把当前余额或净支出冒充历史；预算追踪以退款父项当前预算资格计算。金额始终用Long分值安全聚合，图表浮点仅用于绘制比例。

视觉量化采用实测资源：页面边距/圆角16dp；一级标题18sp正常字重，卡标题15sp、说明11sp，首页主金额26sp；更多卡基准84dp。图表可用宽度比例为环图0.48、折线0.28、柱图0.40，折线2dp平滑渐变无常驻圆点，环图内孔75%。不能统一给所有卡或图固定大高度；大字号时自然增长、不截断。

借还、预算、资金账户、存钱、CSV等已有业务写入仍走原Command/单写门，不能为了UI相似另存余额或绕开授权。面板配置属于业务偏好，应用锁与授权不进入业务备份。

## 工作分区与审阅

- 图表/密度作者：Theme、FinanceComponents、HomeScreen、StatisticsScreen及新增可复用图表/面板UI。
- 二级页/入口作者：Profile、Accounts、Obligation、Recurring、Savings、FileAndRecycle、Entry、More；与公共组件作者确认签名。
- 数据/配置作者：core面板配置/聚合、storage读投影、相应测试与presentation专用DashboardController；先冻结API。
- root：DawnYewApp接线、GenerationRepository平台代理、Android真机交互/截图、唯一Gradle与签名、集成文档。

先由三位审计agent交叉审阅本纠正方案和职责/API，再实施。实现后进行非作者review；以对照图片和实际点击开关/返回/详情作为UI证据。

## 必须完成的验证

1. 配置解析/命令/完整校验/批次恢复；缺键默认与严格旧备份兼容，开关排序恢复；真实Room重开与v2备份往返。
2. 16统计与新增首页面板的core/SQL对照：退款、未入账、转账、归档账本、跨月年、无账户/无维度、多标签、极大金额、范围外坏payload；不得全空假绿。
3. Controller的不同面板请求、代际失效和旧响应拒绝；真实UI开关→主面板显隐→重进/重启保持、排序→显示顺序；每个保留二级入口实际访问。
4. 同分辨率参考/新图对照：5Tab、2配置页、默认3图详情、账户/周期/存钱/借还详情、记账表单；核首屏信息密度、图表类型/轴/颜色、卡/行高度与文案。
5. 最终离线check、签名Release、JNI/权限/对齐核验，独立代码与视觉review。旧376测试数量不能替代本轮实际回归结果。

## 后续用户明确纠正：拖拽与原版资源

- 所有已有排序统一长按拖动，拖动项浮起、相邻项弹性让位、松手吸附、边缘自动滚动；删除上下移动和伪置顶排序按钮。
- 首页面板落位直接保存，主页从同一份已提交布局实时排列；开关同源，不需要保存按钮或重启。修改配置后首页从新首卡开始，未改布局的详情返回保留滚动。
- 账本、分类、账户、项目/商家/标签采用完整作用域的单次原子重排。拖起冻结版本，取消/并发变化不提交，失败还原；隐藏与归档对象保留原槽，同账本/类型才可交换。
- 用户明确要求直接复用APK恢复的可用图形资源。源/目标SHA与用途见reference-artwork.json；颜色/尺寸取自已恢复XML。Android从本地打包资源加载，动态图表和拖动以真实数据驱动。
- 必须真机长按拖动并验证主页顺序、返回/重开及备份恢复；调用数据API或点击上下按钮不能代替手势验收。

## 追加：交互与样式一致性

- 拖动项不参与 Lazy 列表 placement 动画；仅相邻项让位，拖动项跟手，UP 后从当前画面坐标自然进入预留槽。保存失败也从当前画面位置恢复，不能重复播放交换动画。
- 设置、我的、更多进入二级页后返回恢复原列表 index+offset；状态受数据集和授权 generation 隔离。
- 分类管理及同类可排序管理行共用 `ReorderSettingRow`，主页面板是样式唯一依据：16dp圆角、横16/纵12dp内边距、bodyLarge标题/bodySmall副文、36×22dp紧凑Switch、16dp行间距。不得再单独放大Switch或DashboardCard嵌套TextButton撑高行。
- 分类保留启用/停用、流水、重命名/删除；账本与项目/商家/标签无“启用”模型，不人为新增开关，用共享行的无开关变体及紧凑管理菜单。只读账本仍可看流水，写操作禁用由独立toggleEnabled表达。
- 验收补分类开关与重命名取消的真实触摸、分类/账本/项目截图和主页面板同屏对照；不以使用相近颜色代替复用同一组件。

## 追加：记一笔单页与操作密度

- 首页/流水的加号直接创建进程内 EditorDraft 并进入记一笔，删除金额前置页面；账单编辑、退款与OCR仍进入同一表单并保留原约束。
- 主体按参考transaction_add的weight正文+固定保存布局：支出/收入/转账与账本顶行、48dp金额、两行常用分类+全部、账户、同页快捷标签+全部、备注/日期；项目/商家/新建维度/入账/预算/对账放更多选项。
- 正常约360×680dp正文使用同页4×5键盘与固定保存行；底部控件不被正文推走。小窗口/大字体默认收起自定义键盘，系统IME与自定义键盘互斥，主体保留可滚动应急空间。
- 金额键直接更新EditorChange.Amount，EditorDraft.command原有AmountCalculator使用精确分值计算表达式；不在UI另造浮点金额或绕开OCR确认/重复检查。
- 常用路径必须真机点击加号→金额12.34→分类购物→标签→保存，全程无整页scroll；另验3+4保存并继续、原选择保留与新operationId。编辑/OCR/退款路径补源码审阅与实图，不能因压缩删掉确认或低频字段。
