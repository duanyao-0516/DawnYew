版本：0.3。日期：2026 年 10 月 18 日。状态：需求与 UI 方向已评审，可作为技术设计输入；尚未冻结为开发基线。

DawnYew 是一款免费、无需登录、完全离线的个人记账工具。使用者按用途建立多个本地账本，记录收支、查看统计，并通过文件备份保护和迁移自己的数据。Android 首发，技术方向优先考虑 KMP 与 Compose Multiplatform，为后续其他系统适配保留边界，HarmonyOS 不在支持范围。

这份草案用于确认“做什么、规则是什么、如何验收”。具体视觉样式、数据库选型、依赖版本、模块目录和排期在后续阶段确定。依据见[记账产品调研](../../research/2026-10-18-accounting-market-research.md)与[离线快速记账专项调研](../../research/2026-10-18-offline-capture-and-data-research.md)。

交互与视觉设计的工作基线见[交互与 UI 规范 v1.0](2026-10-18-dawnyew-ui-interaction-standard.md)，采用 Material 3 稳定组件与 Android Adaptive，并明确首轮出图范围；本需求中的账务和数据保护规则保持适用。

## 用户与目标

首要用户是希望把日常消费、旅行、装修或兴趣开销分开记录的本机使用者。即使账本叫“家庭”，首版也只有一个本地使用者，不存在家庭成员账号或远程共同编辑。

需要完成的任务：

1. 消费后快速记一笔，并清楚知道记在哪个账本。
2. 回答某个用途这个月花了多少、主要花在哪里。
3. 修正金额、分类和账本归属，处理退款而不重复计算收支。
4. 不依赖网络和账号，保留、导出并恢复自己的记录。

成功标准是完成上述闭环且账目一致，不以功能数量或竞品宣传的“几秒记账”作为成功证明。

## 产品方案与术语

采用“多个独立用途账本”的建议方案。单账本加标签的隔离能力不足；虚拟资金池会引入资金分配、期初和余额核对，超出当前范围。三种方案的比较见调研文档。

| 术语 | 本项目含义 |
| --- | --- |
| 账本 | 按用途组织账单的本地容器，如日常、旅行、装修 |
| 分类 | 账本内部的收入或支出种类，如工资、餐饮、交通 |
| 流水或账单 | 一条已保存的收入、支出或关联退款记录 |
| 收支结余 | 指定期间收入减去净支出，不代表银行余额或实际可用资金 |
| 预算 | 某账本某自然月的消费计划，不是向账本充值 |
| 全部账本 | 跨账本的统计视图，不是另一个可存流水的账本 |
| 移动账单 | 修改账本归属，不是产生收支，也不是资金转账 |
| 备份 | 能恢复账本、分类、流水、关联关系和设置的完整文件 |
| JSON 数据文件 | 带版本的完整数据协议，可用于完整恢复；明文文件与口令加密备份容器明确区分 |
| Excel 文件 | 真实 .xlsx 流水交换文件，不代替完整备份 |
| 识别草稿 | 尚未记入统计、待用户检查的截图识别结果 |
| 应用锁 | 使用设备生物识别或系统凭据保护本地应用入口，不是联网登录 |

## 主要用户流程

### 首次使用和分账本

首次打开直接进入空的“日常”账本；说明数据保存在本机，并提供“创建账本”和“恢复备份”。不先索取手机号、联网许可或全部文件访问权限。

从账本入口创建“旅行”，选择名称及本地内置图标，可复制一组默认分类。切换后首页、流水、统计与预算都显示旅行账本；输入页始终显示归属。模板复制后分类独立，修改旅行分类不会影响日常。

### 记录和纠错

在当前账本点击记一笔，默认支出、当前日期，选择分类并输入金额后保存。备注和历史日期可按需修改；保存成功必须意味着数据已经落盘。“再记一笔”保留账本与所选分类，清空金额和备注。

记错账本时，从详情选择移动，明确目标账本与目标分类，确认后迁移原记录。两个账本统计同时更新，全部账本总额不变。

### 月度复盘

选择账本和月份，查看收入、原始支出、退款、净支出及结余，从分类排行下钻到同一筛选条件的流水。设置月预算后显示已用、剩余或超支。切换到“全部账本”看合计及按账本分布，不自动将不同账本的同名分类合并。

### 备份和恢复

从数据管理选择“完整数据 JSON”或“口令加密备份”，保存到用户选择的本机文件位置。JSON 明文导出前展示数据范围与明文说明；加密备份需用户设置口令。恢复时先验证口令或格式、数据完整性及版本，再预览日期、账本数和流水数。用户确认替换后才变更当前数据；失败保持原数据。首版不合并两个完整备份。

### 表格导入和截图录入

用户选择已保存到本机的微信、支付宝历史账单，或 DawnYew 模板及导出文件；受支持的平台文件可直接解析，无需先人工改成 DawnYew 模板。应用展示来源与格式匹配、账本分类映射、错误行、确定重复、疑似重复、不计入收支项和本次新增合计；确认后一次性导入所选有效记录。已有记录不被隐式覆盖。

用户在支付成功页截图后，通过系统分享给 DawnYew，或在应用内选择图片。应用锁启用时先解锁，再本地识别并显示可编辑草稿；金额、类型、日期、分类和账本检查完成后，用户确认才保存。

### 生物识别解锁

应用锁由用户在设置中启用，启用时通过系统认证。设备有可用的强生物识别时使用系统提示，系统 PIN、图案或密码作为后备；没有可用认证方式时不能显示已启用。锁定状态下明细、图表、导入导出、截图分享等入口均受保护。

### 账本和分类边界

至少保留一个可用账本。不能归档最后一个可用账本；先创建或恢复另一个账本。归档账本默认退出日常选择，但可查看历史，历史总览默认仍包含它，并明确显示是否包含归档数据。归档后若需修改、收退款或接收移动，先取消归档。

空账本可删除；含有效或回收站流水的账本只提供归档，避免一键误删大量数据。用户仍可通过数据管理的“清空全部数据”主动擦除所有内容。

账本名称去除首尾空白后非空，最长 30 个字符，同一本机库不允许重名；分类名称最长 20 个字符，在同账本同类型内不允许重名。备注最长 500 个字符。使用稳定标识维持关联，不能用名称当关联键。

分类停用后不出现在新建选择中，历史仍可查看。重命名作用于该分类的历史展示。新分类、停用或改名均不应改变既有金额。

### 金额和时间规则

首版仅人民币，金额精确到分，输入金额必须为正数。零金额、负数、超过两位小数、无效文本和大于 999,999,999.99 元的单笔金额均提示纠正，不静默舍入。统计计算不得出现二进制浮点累积误差；汇总溢出要显式报错，不能截断或回绕。

类型决定金额的业务含义，不用负数伪装退款。收入、支出只能从相应类型分类中选择。暂不支持预约未来记账；发生时间晚于本机当前时间时要求修改。

账单按用户录入的本地发生日期归属自然日和自然月。修改设备时区或跨平台恢复后，不自动把既有账单挪到其他月份。创建时间与发生时间分开；补记按发生时间统计。期间筛选包含起止日期的整天。

### 退款规则

退款从支出详情创建，与原支出归属同一账本和分类，日期不早于原支出。有效退款合计不得超过原金额；修改原支出金额到已退金额以下，或将原支出日期移到任一有效退款之后时拒绝保存。有退款关联时不直接将原支出改成收入，须先处理关联记录。

原支出修改分类时，关联退款的分类归属随之更新。移动原支出时，关联退款一起移动并映射到目标分类；不允许单独将退款移动到另一本。

退款按实际退款发生月份抵扣当月净支出，不回写原消费月份。该选择使每月记录反映当月发生的收支变化，必须在统计说明中可见。

| 指标 | 口径 |
| --- | --- |
| 收入 | 期间内收入记录合计，不含退款 |
| 原始支出 | 期间内支出记录合计 |
| 退款 | 期间内关联退款记录合计 |
| 净支出 | 原始支出减退款，可以为负数 |
| 收支结余 | 收入减净支出 |
| 预算已用 | 本账本当月净支出与 0 中的较大值 |
| 预算剩余 | 设定预算减预算已用；为负时展示超支金额 |

例如 9 月支出 100 元、10 月收到 30 元退款：9 月净支出仍为 100 元；10 月没有其他支出时净支出为 -30 元，退款不是收入，10 月预算已用为 0。退款不会把“预算剩余”抬高到设定预算以上。

### 移动与删除规则

跨账本移动必须选择目标分类；同名分类不自动视为同一个分类。原支出及其退款作为完整一组移动，全部成功或全部不变。两个账本的历史统计和预算占用同时重算，不产生虚构的转出收入或转入支出。

删除原支出时，确认提示展示关联退款数量，并将原支出与当前有效退款一起放入同一删除组；此前已单独删除的退款保持原删除组，不因恢复原支出而自动复活。单独删除退款时只冲回该退款影响。编辑回收站记录前须先恢复。回收站不参与任何统计，首版不按时间自动清空。

恢复时重新校验原支出有效性、日期、分类、账本状态及退款累计上限；一组中任一项不满足则整组不恢复，并说明冲突。原支出移动或改分类后，回收站退款保留原关联 ID，恢复时跟随原支出的当前归属并重新校验。不得因恢复旧退款而超额退款。

永久清理原支出时才级联清理其全部退款；永久清理单条退款绝不反向删除仍有效的原支出。清空全部数据须说明包含账本、分类、流水、回收站和应用内部保护副本，二次确认后回到初始状态；用户已保存到外部位置的备份不会被自动删除。

### 统计和预算规则

收支统计和列表使用相同过滤条件，卡片数字必须能下钻核对。预算始终按指定账本完整自然月计算，不受类型、分类或备注筛选影响；带有这些筛选或非整月范围时隐藏预算模块。全部账本汇总只聚合真实记录一次，不保存复制流水。分类统计先按账本区分，同名不同 ID 的分类不自动合并。

分类图展示原始支出占比；退款和净支出在分类明细中单列。净支出为负时不绘制误导性的负数饼图。无数据时显示空态和记账入口，不显示模拟账单。

月预算自愿设置，必须为正数；各月独立，首版不结转、不自动继承、不划拨额度。超过预算不阻止真实记账，只显示超支。账本无预算时不计算预算使用率；全部账本页不把各账本预算视为共享额度。

图表包含：按日或月的收入与净支出趋势、原始支出分类占比、账本支出对比、预算进度。趋势粒度随月和年范围明确显示，缺少记录的日期按零记录值补齐，不意味着应用已掌握全部真实消费。负净支出使用明确零轴和方向；占比图只用非负的原始支出。

点击趋势点、分类或账本柱条下钻到对应明细，退出后保留原筛选。每张图提供等价数据表、单位和口径说明；预算超出 100% 时仍展示真实比例与超支金额，不能只画满格。

### 备份与导出规则

完整备份包括账本、分类、流水、退款关联、预算、回收站、导入批次、稳定标识和必要偏好。备份中不包含设备绑定的安全凭据；应用锁在新设备重新设置，同设备恢复不能关闭现有应用锁。

完整数据协议使用带版本的 JSON，金额使用整数分或明确十进制定长字符串，不能由浮点解析改变金额。明文 `.json` 可独立导入导出；另提供默认推荐的口令加密备份容器，使用不同扩展名，解密后仍为同一 JSON 协议。导出时明确两者的数据范围和保护差异。忘记口令时无服务器找回，应用不保存口令明文；密码派生和加密算法在系统设计阶段选择成熟实现。

恢复为整体替换，不是追加；重复恢复同一份备份不得产生重复流水。恢复前先在本机创建当前库的保护副本，空间不足则取消恢复。损坏文件、错误口令或不受支持的未来格式版本均保持现有库不变。成功后核对账本数、记录数、关联完整性及各期间合计。

完整 JSON 与加密备份不采用 XLSX 的行数或文件大小限额。应用成功生成的完整备份，在支持该格式且存储空间充足的环境中必须能够恢复全部数据；解析须分段处理并可取消，不能通过限制备份记录数掩盖内存问题。导出和恢复前检查所需空间，失败不生成看似成功的残缺文件，也不破坏现有库。

JSON 恢复前验证全部字段、金额范围、ID 唯一性和引用关系；无效退款、跨本分类、重复 ID 等导致整次恢复失败。已有库的保护副本不被导入文件里的偏好、锁状态或名称覆盖。明文 JSON 必须可在应用外阅读，不能仅把私有二进制改成 `.json`。

DawnYew 的 Excel 模板和导出文件使用真实 `.xlsx`，均支持再导入。首版同时直接支持微信、支付宝历史账单文件：文件类型、表头、编码、日期格式、状态和字段映射以用户后续提供并确认的模板为准，不能预先假定两平台都使用 XLSX，也不要求用户先改为本应用模板。支持的模板及版本需有兼容清单，格式不匹配时说明原因且不写入数据；不承诺兼容任意第三方账单。

本应用表格导出金额为数值单元格，名称、时间和备注为明确文本，文字公式前缀不执行；表格导入中出现公式、外部链接或无法识别的字段类型时标记错误，不计算公式或读取缓存值当成已确认金额。DawnYew 自身模板不采用老 `.xls`、含宏 `.xlsm` 或加密工作簿；平台原始文件的格式与解包需求在样本确认后另行定界，不因为当前模板未知就排除用户要求的历史导入。

DawnYew 自身表格的候选业务字段包括记录 ID、账本、类型、分类、金额、发生时间、备注、原支出 ID，以及历史导入记录可用的来源标识，并带独立的模板版本与字段说明。这些是信息需求，不是已确定的列名或布局；待用户提供模板细节后确定。自身模板建议日期时间使用明确的 `YYYY-MM-DD HH:mm:ss` 文本；不自动猜测含糊的日月顺序。导出范围由筛选和用户确认决定，退款的原支出即使在范围外也保留关联 ID，并提示该文件是否含未随文件导出的引用。

历史账单及表格导入是“新增有效流水”，不是完整恢复或自动改写已有记录。导入前必须确认目标用途账本和分类映射，不能仅凭来自微信或支付宝自动选择用途账本；缺失的账本分类可在预览中显式选择创建。相同 DawnYew ID 且规范化内容相同的记录跳过；相同 ID 内容不同为冲突，首版不自动覆盖。无 ID 时，同日同金额仅为疑似重复，用户选择保留或跳过。退款须能关联同批次或本库中的原支出，找不到则标为错误，不转换成普通收入。

平台来源与 DawnYew 记录身份分开保存。去重优先使用经模板验证具有唯一性的来源范围及原始流水标识，不能把微信和支付宝的同值编号、不同来源范围的编号当作同一记录；无法验证唯一性时只提示疑似重复。相同来源身份且来源内容未变可跳过并保留本地修改，不能因记录改分类或移动账本就导入新流水；来源金额、状态等变化则提示冲突，不静默覆盖。为此保留必要的规范化来源信息，与用户修改后的本地字段分开比较。平台文件与已有手动或截图记录重叠时，同金额同日期仍只能提示。稳定来源信息随完整备份和本应用表格往返保留，防止迁移后重导产生重复；无需接入平台账号、余额或联网验证。

平台行先按已确认模板识别实际业务语义：可确认的收支才形成候选流水；失败、关闭等未实际成交项明确列为排除项。转账、充值、提现、还款等不得直接全部算作消费或收入；“转账”也不能一概排除，须区分内部资金移动和真实对外收付款，预览中展示原因，歧义项须人工处理。退款仍遵守关联原支出与累计上限；仅有累计退款状态、缺少可确认退款事件信息时进入待处理，不能臆造日期或金额，也不能同时用净额支出和独立退款重复抵扣。平台汇总行、说明行不当流水导入。各类状态与类型的具体值待样本确认，不猜测映射。

用户可剔除错误或冲突行后重新校验，只有所选记录及其依赖全部有效才能确认导入；映射创建、流水和批次记录一次性提交。失败不留下半个批次。预览和结果展示有效新增、确定重复、疑似重复、错误或冲突、明确排除的数量与收支合计，不能静默丢行。重复导入未经改动的本应用导出文件应跳过已有 ID；对不带稳定身份的外部记录保留疑似重复确认，不能保证自动判重。

导入批次可查看新增数、跳过数和影响合计。在本批新增流水未被后续编辑、移动、删除或被批次外退款引用时，可确认撤销本批新增流水；否则提示受影响项并拒绝整批撤销，避免误删后续记录。撤销原子化移除本批流水及其批内退款并标记批次已撤销，不回滚原本已存在的数据；导入时创建的账本和分类一律保留，确认页明确这一点，空容器可由用户另行管理。JSON 与 Excel 的保护、导入方式和适用范围在入口处说明，不用 Excel 代替完整备份。

应用通过系统文件能力读写用户选择的文件，不申请全部存储访问权限。验收以本机文件为准；用户自行把导出文件交给云盘或其他应用，不属于 DawnYew 自动同步能力。应用内部保护副本不能替代设备外备份，卸载或设备损坏后不能承诺找回。

微信、支付宝账单由用户自行从对应平台取得并保存到本机；DawnYew 负责本地解析，不登录支付平台、不抓取在线账单、不接入银行。后续模板信息需明确来源与版本、文件容器和编码、字段含义、金额时间表达、状态、原始流水与退款关联方式，以及脱敏示例和预期结果；在此之前可继续其他模块设计，导入适配器与对应验收暂不定稿，也不能将支持历史导入标为已完成。

### 本地应用锁规则

应用锁为用户可选能力，首次启用或关闭须成功完成系统认证。优先使用可用的强生物识别；不把所有 Android 面容方案视为同等安全等级。没有符合要求的生物识别时使用系统 PIN、图案或密码；两者均不可用时说明原因并引导设置设备锁屏，不自动启用或解锁。

启用后，冷启动和离开应用再返回均须验证，切换到后台立即遮盖敏感内容及任务预览。由应用主动打开的系统认证或文件选择流程视为本次已授权操作的一部分，返回同一操作不触发无限认证循环；若进程死亡则重新认证。具体生命周期判定需真机验收。

失败、取消、临时锁定或硬件不可用时保持锁定，允许调用已配置的系统凭据后备。分享图片、深链、文件导入等外部入口先经过锁检查，解锁前不显示账单、图片预览或执行识别。共享 URI 已失效时提示重新选择文件，不绕过锁补救。

应用锁已启用时，导出明文、创建备份、替换恢复、清空数据和关闭锁均要求重新系统认证；普通查看和记账在当前有效会话中无需每次再认证。未启用锁的用户仍有操作范围确认。

设备凭据被移除或认证配置改变后，应进入需重新系统认证的状态，不能将异常当作认证成功。没有可用后备时不提供免认证重置入口；本地备份口令也不作为绕过现有库应用锁的密码。应用不持有生物模板，应用锁与数据库、导出文件的加密分别定义。

### 截图快速记账规则

首版主路径为“用户分享或选择单张 PNG/JPEG → 解锁 → 本地 OCR → 字段解析 → 核对草稿 → 保存”。模型随应用交付，首次断网安装即可执行；不得要求临时联网下载模型或回退在线服务。OCR 引擎候选及隐私约束见专项调研，未实测前不锁定供应商。

优先支持微信和支付宝单笔消费支付成功页、单笔消费详情页。首版不自动解析多笔列表、长截图、退款、转账和复杂抵扣场景为正式流水；可展示不支持或待核对状态并转手动输入，不静默猜测。

每次最多生成一条草稿。金额、类型、日期、分类和账本均可修正，未确定或推测字段有明显标识。金额不唯一时要求选择候选；日期缺失时可以建议今天，但必须标为待确认。分类和用途账本通过本地规则提出建议，不仅凭微信或支付宝渠道决定归属。

草稿不参与图表和预算。任何识别结果都须用户确认，正式保存再次执行金额、归属和重复提交校验。疑似重复仅提示用户，不按同金额同日期直接删除；相同草稿重复提交保证只产生一条流水。

取消、权限拒绝、图片失效或识别失败时不修改账本。图片临时副本在取消或保存后清理，进程异常留下的临时内容在下次安全启动清理，不删除相册原图。首版不保存图片附件或原始识别全文，不持续监听相册或读取其他应用页面。

离线语音为待验证的第二候选，不默认依赖系统输入法或普通云识别器。若首版改选语音，必须先按专项调研验证端侧中文覆盖、数字正确性、体积和耗时，再更新本需求及验收。

## 信息组织建议

首版建议使用三个主要页面：“明细”“统计”“设置”，另有固定的“记一笔”入口。账本切换在明细与统计顶部保持一致；账本管理从切换面板进入。

| 页面 | 核心内容 |
| --- | --- |
| 明细 | 当前账本、期间汇总、按日流水、查询筛选、记一笔 |
| 记一笔 | 明确的账本、收入或支出、金额、分类、日期时间、备注 |
| 账单详情 | 完整字段、编辑、移动、退款、删除及关联记录 |
| 统计 | 本账本或全部账本、期间、收支指标、趋势、占比、账本比较、预算、数据表 |
| 账本管理 | 新增、改名、排序、分类管理、预算、归档 |
| 设置和数据管理 | JSON、加密备份、微信/支付宝历史导入、DawnYew 模板与 XLSX 导入导出及批次、应用锁、回收站、外观、本地帮助、清空数据 |
| 截图草稿 | 当前账本、图片预览、识别字段、待核对提示、重复提示、确认保存 |

“全部账本”是只读聚合范围；从这里记账时必须明确选择实际账本。任何删除、恢复替换和清空都先显示影响范围，再由用户确认。

## 概念数据模型

这里只约束业务关系，不规定数据库表结构或框架。

| 对象 | 必须表达的信息 | 关系约束 |
| --- | --- | --- |
| 账本 | 稳定 ID、名称、图标、顺序、归档状态、币种 | 一个账本有多条分类、流水和月预算 |
| 分类 | 稳定 ID、所属账本、收入或支出类型、名称、顺序、停用状态 | 不能关联到其他账本的流水 |
| 流水 | 稳定 ID、账本、类型、金额、分类、发生时间、创建和修改时间、备注、删除状态、可用的导入来源范围及原始流水标识 | 收入和支出独立；有效退款关联同本有效支出；回收站保留原关联，恢复时重新校验；平台来源身份不能替代本地 ID |
| 月预算 | 所属账本、年月、金额 | 同账本同年月最多一个有效预算 |
| 识别草稿 | 来源、临时图片引用、候选字段、待核对项、提交标识 | 确认前不计入流水或统计 |
| 导入批次 | 来源平台或模板、格式版本、文件摘要、映射、新增记录 ID、各类结果计数、撤销状态及时间 | 保留历史引用，记录永久清理或撤销后可标为已移除；不能借撤销批次修改其他已有数据 |
| 本地偏好 | 当前账本、外观、应用锁启用状态、最近一次完整备份时间 | 不保存生物模板、备份口令、登录令牌或云同步状态 |
| 备份描述 | 格式版本、生成时间、对象数量、完整性信息 | 恢复后稳定 ID 及业务关联保持不变 |

不引入用户账号、银行账户、余额、债务、云同步队列或共享成员。统计是流水的派生结果；即使以后缓存，也必须能从原记录重建。

| NFR-04 | 本地数据升级可恢复 | 旧格式样例升级后逐项核对；失败保留旧数据及保护副本，不清库重建 |
| NFR-05 | Android 首版建议性能目标 | Release 构建、20 本共 10,000 条流水、固定 Android 12 及以上 6GB 中端真机；冷启动 P95 ≤2 秒、保存 P95 ≤300 毫秒、月份切换 P95 ≤500 毫秒，各测 100 次并记录设备和版本 |
| NFR-06 | 核心路径可理解 | 5 名首次使用者至少 4 名可无指导完成创建账本、记一笔、移动和查统计；熟悉后记一笔中位耗时 ≤10 秒；仅作首轮可用性门槛 |
| NFR-07 | 基本无障碍和可读性 | 支持系统字号放大、深浅色、屏幕阅读器标签；金额和收支不能仅靠颜色区分 |
| NFR-08 | 隐私边界可解释 | 日志不含完整账单、备注或备份口令；不宣称本地存储等于数据库加密或数据永不丢失 |
| NFR-09 | 跨平台规则一致 | 账务计算、日期归属和备份格式不依赖 Android 类型；后续平台用同一组业务样例验收 |
| NFR-10 | 截图快速录入达到实际价值和离线门槛 | 按专项调研的 240 张样本、至少三厂商真机、首次断网、准确性及全流程耗时验证；未通过不得宣称功能完成 |
| NFR-11 | 外部文件解析资源可控、可取消 | 历史账单和表格交换导入暂定单文件 ≤20MB、≤10,000 条流水、如有压缩则解压总量 ≤100MB；最终限额须结合确认的三类来源样本评审，超过先拒绝并说明。完整 JSON/加密备份采用分段解析、空间预检及结构校验，不套用交换导入容量限制；须通过超过该限额的完整往返验收。畸形文件、压缩炸弹和超大图片不导致部分写入或主界面失去响应 |

性能数值为建议验收目标，不是已有测量结果。系统设计阶段需锁定实际基准机和最低系统版本；未经该环境测量不能宣称达到目标。

## 验收场景

| 编号 | 给定与操作 | 期望结果 |
| --- | --- | --- |

| AC-04 | 归档旅行账本；尝试归档最后一本 | 历史可查，默认新建列表排除旅行；最后一本拒绝归档并说明原因 |
| AC-05 | 停用已用分类、修改另一账本同名分类 | 旧记录可查，停用分类不可新选；其他账本不受影响 |
| AC-06 | 输入 0、负数、三位小数和超上限金额 | 不保存且提示；0.10 与 0.20 合计精确为 0.30 |
| AC-07 | 对同一保存动作连续快速点击，保存后立即结束进程 | 仅保存一条；成功提示后的记录重启仍在 |
| AC-08 | 支出 100，退款 30 再退 20，再尝试退 60 | 前两次成功；净支出 50；超额退款失败且原数据不变 |

| AC-10 | 将一笔支出及两条退款移动到旅行并选目标分类 | 三条同组移动，ID 不变；两个账本重算，总览金额不变 |
| AC-11 | 修改金额或日期后按类型分类备注筛选 | 收支明细和图表遵守筛选；预算隐藏，回到整月视图仍按完整账本月份计算 |
| AC-12 | 有跨午夜月底记录，修改设备时区，再查同一月份 | 未主动编辑的流水不迁移月份；汇总与下钻合计相同 |
| AC-13 | 当月退款大于支出或筛选无结果 | 明确展示负净支出或空态，不伪造饼图和样例记录 |
| AC-14 | 本月预算 500，净支出 550，再退款 100 | 先显示超支 50，后显示剩余 50；未设预算的其他本不受影响 |
| AC-15 | 完整备份后在空数据环境恢复，再重复恢复 | 账本、分类、流水、关联、预算、回收站及汇总一致；无重复记录 |
| AC-16 | 用错误口令、损坏文件、未来格式或空间不足尝试恢复 | 明确失败，当前库和已确认的数据不变 |
| AC-17 | 导出带逗号、引号、换行和公式前缀备注的 XLSX | 文件可由标准 Excel 工具打开，文本不执行公式；金额、数量与筛选一致 |
| AC-18 | 删除带退款支出、恢复；再单独删除一条退款 | 整组删除恢复一致；单删退款只影响该退款；回收站不参与统计 |
| AC-19 | 先取消、再确认清空全部数据 | 取消不变；确认清除本机业务数据及内部保护副本，外部备份保留 |

| AC-21 | 在统一基准设备运行性能和可用性样例 | 输出 NFR-05、NFR-06 的实测记录，不用宣传语替代结果 |
| AC-22 | 支出 100、退款 100，删掉退款后再退 100，再恢复旧退款 | 恢复被拒绝，累计有效退款仍为 100；恢复整组失败不部分生效 |
| AC-23 | 单独删除一条退款后永久清理该退款 | 原支出与其他有效退款保留；仅清理已选退款 |
| AC-24 | 查看趋势、占比、账本比较和预算，点击图表下钻 | 指标、单位、期间与明细吻合；负值、无数据、仅收入和超支均可理解；数据表等价 |
| AC-25 | 同一份本应用 XLSX 连续导入两次，再导入同 ID 改金额版本 | 第二次跳过已有记录；同 ID 改内容提示冲突且不覆盖 |
| AC-26 | 模板包含新分类、缺原支出的退款、无 ID 同日同额记录和公式 | 预览显式映射；错误及未处理歧义不能提交；用户选定有效集后原子化导入 |
| AC-27 | 导入中断或尝试撤销已被后续编辑的批次 | 中断无半批数据；不允许整批误删后续修改或关联，不影响已有数据 |
| AC-28 | 明文 JSON 往返及导入重复 ID、损坏关联、未来版本 | 合法完整数据可恢复，非法文件不覆盖；同设备恢复保持现有锁保护 |
| AC-29 | 已启用锁时冷启动、后台返回，认证失败或取消 | 内容保持遮盖，不进入账单；系统凭据后备按实际可用状态提供 |
| AC-30 | 锁定时从截图分享、文件和深链入口进入，再导出或恢复 | 外部入口不能绕过锁；敏感操作重新认证；取消无数据副作用 |
| AC-31 | 无生物硬件、有系统 PIN，或所有认证能力均不可用 | 前者可用系统凭据；后者不能假启用或自动放行；认证/文件选择返回不陷入循环 |
| AC-32 | 全新安装后断网识别支持范围截图 | 无模型下载，生成可编辑草稿；未确认前统计不变；确认后仅一条流水 |
| AC-33 | 多金额、退款、失败支付、模糊或已导入截图，取消或重复提交 | 歧义或不支持明确提示；已导入截图提示疑似重复，用户可主动保留；均不自动入账。取消不变，同一草稿重复提交不重复；原相册图片保留 |
| AC-34 | 完成专项 OCR 样本和耗时试验 | 记录实际准确性、冷启动、内存及完整耗时；不达门槛则重新评审，不宣称最佳或验收通过 |
| AC-35 | 历史账单或表格导入超限、任一格式畸形或恶意压缩文件，处理中取消 | 界面可恢复、无部分写入；明确说明拒绝原因；不因普通完整备份超过交换导入限额而拒绝 |
| AC-36 | 导出超过 10,000 条流水且大于 20MB 的完整 JSON 和加密备份，再在受支持且空间充足的环境恢复 | 全部数据及合计一致，不受 XLSX 导入限额阻断；处理可取消，取消保持原库 |
| AC-37 | 导入时创建账本和分类，随后手动在该分类记账，再撤销未改动的原导入批次 | 仅移除本批新增流水，保留手动记录、账本和分类；重复撤销不再次改变数据 |
| AC-38 | 断网选择已确认格式的微信、支付宝原始历史账单，以及 DawnYew 模板与自身导出文件 | 三类来源均可直接预览，不要求人工改表；选择用途账本后原子化导入。模板样本待补充，当前不能宣称通过 |
| AC-39 | 重复及交叠期间平台文件、本地改分类或移动后重导、不同平台同值流水号、同来源身份金额或状态变化，以及已有手动/截图同额记录 | 可确定的重复跳过并保留本地修改；不同来源身份不碰撞；来源变化提示冲突；模糊重复由用户判断。完整恢复或自身表格往返后，保留来源信息的记录仍按同一规则判重 |
| AC-40 | 确认样本包含收支、失败或关闭项、资金划转类、退款和汇总说明行 | 按确认的语义预览新增、排除及待处理项；退款关联有效原支出且不重复抵扣；行数和影响合计可核对，无静默丢行 |
| AC-41 | 选择未知模板、变化的表头、无法确认的日期编码或退款缺失原支出 | 不猜测导入；说明不兼容或具体错误，现有数据不变；支持版本与规则以已确认模板为准 |

## KMP 与 Compose 的技术方向

建议采用 KMP 共享业务逻辑和 Compose Multiplatform 共享主要界面。官方将 Android、iOS 和桌面 JVM 支持列为稳定，适合 Android 先交付、后续扩展的目标。[平台支持](https://kotlinlang.org/docs/multiplatform/supported-platforms.html)

可共用的部分包括账本与分类规则、金额与退款计算、图表数据、预算、JSON 协议、导入校验、识别后的字段规则、界面状态和大部分页面。需要隔离的平台能力包括文件选择、文件写入授权、系统备份排除、生物识别、图片识别、日后录音、生命周期和小组件。XLSX 读写库与图表库还须单独验证目标平台兼容，不能因为 Kotlin 接口就认定跨平台可用。[平台 API 边界](https://kotlinlang.org/docs/multiplatform-mobile-connect-to-platform-specific-apis.html)

Android 是首版产品验收平台；iOS 作为后续扩展目标，桌面不承诺首版交付，HarmonyOS 排除。按最新用户范围，当前只定义iOS所需平台接口和平台无关数据协议，不建工程、不实现适配、不执行iOS编译验证；以后正式启动iOS开发时再验证共享层和系统文件/认证能力，不宣称已经兼容。

需求阶段不锁定数据库、依赖版本或代码复用比例，也不因为选择跨平台框架加入服务器或多端实时同步。

## 已评审方向与保留事项

1. 采用“用途账本”模型和名称，排除资金池、账户余额与内部转账。
2. 沿用表中 P0 组合：图表、JSON/XLSX、应用锁和截图 OCR 是重点，月预算、退款与回收站构成完整账务闭环。
3. 沿用截图 OCR 先验证、语音后置的路线，以及退款按发生月份抵扣、账单移动整组处理、完整恢复整体替换、XLSX 仅新增的规则。OCR 不达既定门槛时返回需求评审，不自行降级 P0。
4. 沿用中文、人民币单币种、Android 首发及 iOS 后续适配方向；最低系统版本、基准机和跨平台可行性由技术设计明确。

已确认的“不联网、不收费、不做银行资产负债、不支持 HarmonyOS，以及首版支持微信/支付宝历史导入和 DawnYew 自身模板与导出文件再导入”无需重复确认。模板细节仍等待用户后续提供；后续变更须同步范围、业务规则和验收场景。当前为技术设计输入基线，具体适配规则及技术验证完成后再形成开发基线。
