# Debug 测试数据工具实施计划

> 使用 subagent-driven-development：领域批量写入由子代理实施，主线程实现二级页面与入口，完成后独立交叉 review。

**Goal:** 长按底栏「我的」进入 Debug 二级页，可向选定账本批量生成指定日期范围和数量的测试账单。

**Architecture:** 生成命令在已有仓库事务内执行，以明确的 debug 批次复用导入成员和撤销校验；不逐条提交，不绕过领域校验，不修改数据库结构。页面通过现有 AppController 提交及恢复协议处理忙碌、失败和确认。

**Tech Stack:** Kotlin Multiplatform、Compose Material 3、现有 Room 与领域命令，无新增依赖。

## 设计约定

- 普通点击「我的」行为不变；长按进入「Debug」并将返回来源设为「我的」。提供长按无障碍语义。Debug 在当前开发签名的 Release 同样可用。
- 默认选未归档的「日常」账本；若不存在则选择首个可写账本并显示实际名称。日期默认含今天的近 30 天，数量默认 100。
- 可选择账本、起止日期和 1–10,000 条数量。日期不可晚于本机今天；当天时间不超过当前时间；无可用分类、已归档/丢失的账本或无效参数明确拒绝，不自动创建账本或分类。
- 生成数据覆盖所选日期，按可用收支分类产生变化的金额和备注；备注含「DEBUG 测试」。不伪造真实支付来源、OCR 或导入文件。
- 单个生成命令在一个事务内追加精确数量，不改已有账单。批次采用独立 adapter 标记，支持命令幂等与操作回执恢复。
- Debug 页提供批次列表及按批次撤销；复用完整性保护，被编辑、删除、移动或关联额外退款的批次拒绝整批撤销。撤销按钮明确提示只删除该批测试数据。
- 提供本地数据概览与生成反馈，不额外加入与本请求无关的调试开关。
- 保留当前 checkout 已存在的更多页工具。沿用既有授权完成主机测试、构建、签名、覆盖安装及提交推送；不在用户真机实际造数、不再操作验证手机。
